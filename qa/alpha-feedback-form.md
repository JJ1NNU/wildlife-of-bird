# 친구 알파 피드백 양식

> 관리: QA·밸런스. 상태: **v0.1 초안 — 잠정(#542)** (M3, #539). M3 관문 "친구 알파 피드백"의 근거다(02-roadmap 6장 M3: `qa/reports/alpha-feedback.md`에 응답 3명 이상 — 잠정, 대표가 바꿀 수 있음).
> 쓰는 법: 대표가 친구에게 PM 안내문(`docs/studio/alpha-plan.md` 3장) 뒤에 이어 **아래 "친구에게 보낼 글"만** 메신저로 보낸다(GitHub 계정이 필요 없게). 친구는 답을 메신저로 돌려준다. 대표는 받은 답을 그대로 `type:human` 알파 이슈에 댓글로 붙인다(이름은 별명·이니셜로). QA가 읽어 정리한다.
> 친구의 시간을 아끼려고 짧게 만들었다. 예상 소요: 플레이 20~30분 + 답 5분. 모든 질문은 건너뛰어도 된다.

---

## 친구에게 보낼 글 (복사해서 보냄)

```
폰 브라우저로 아래 주소를 열면 바로 할 수 있어. (설치는 안 해도 됨)
주소: <빌드 주소>

20~30분쯤 해 보고, 아래에 짧게 답해 줘. 모르겠거나 귀찮은 건 건너뛰어도 돼.

1. 폰 기종 / 브라우저: (예: 갤럭시 S23 / 삼성 인터넷)
2. 얼마나 했어? 대략 몇 분, 새가 몇 번 죽었어? (계승한 새끼 세대 포함)
3. 처음 화면에서 뭘 해야 할지 바로 알았어? (예 / 조금 헤맴 / 많이 헤맴) — 헤맨 곳이 있으면 어디?
4. 새가 죽었을 때 왜 죽었는지 납득됐어? (예 / 대충 / 아니)
5. 가장 재밌었던 순간 하나
6. 가장 지루하거나 짜증 났던 순간 하나
7. 또 해 보고 싶어? (1 전혀 ~ 5 꼭)
8. 이상하게 동작한 것 (버튼이 안 눌림, 글자가 잘림, 멈춤 등) — 있으면 어디서, 화면 캡처 있으면 같이. 새가 죽은 화면의 "플레이 기록 저장" 버튼으로 받은 파일도 있으면 보내 줘(무슨 일이 있었는지 그대로 다시 볼 수 있어)
9. 새에 대해 "이건 사실과 다른데?" 싶은 게 있었어?
10. 자유롭게 한마디
```

## QA 정리 규칙 (QA용)

- 응답마다 `qa/reports/alpha-feedback.md`에 한 줄 표로 옮긴다: 응답자(별명) · 기기·브라우저 · 플레이 분 · 3·4·7번 답 · 문제 수. 아래에 5·6·10번 답을 요약한다(원문 인용은 짧게).
- **관문 판정**: 응답 3명 이상이 정리되면 "친구 알파 피드백" 통과(잠정 기준 — 대표가 바꿀 수 있음). 응답 수와 이슈 링크를 리포트 결론에 적는다.
- 8번 문제는 QA가 재현을 시도해 `type:bug` + `sev:` + 담당 부서 라벨로 연다. 재현 정보는 QA가 채운다 — 친구에게 다시 묻지 않는다. 기록 파일(`wb-run-<시드>.jsonl`)이 오면 `npm run sim -- replay`로 먼저 돌린다(`commit`과 `startCommit`이 다르면 배포를 넘은 판이라 리플레이 대상 아님 — 그 커밋에서 화면으로 재현). 재현이 안 되면 그대로 적고 S3 이하로 둔다. 기기·브라우저가 원인이면 그 정보를 꼭 적는다.
- 다른 답은 부서 이슈에 요약해 넘긴다: 3 → design(튜토리얼·온보딩)·client · 4·5·6·7 → design · 9 → content · 1(기기별 문제) → client.
- 같은 말을 2명 이상 하면 리포트에 "반복된 의견"으로 따로 묶는다.
