# 알파 피드백 양식 (대표 혼자 여러 판)

> 관리: QA·밸런스. 상태: **v0.2 — 잠정(#607)** (M3, #539). M3 관문 "알파 피드백"의 근거다. 대표 결정(2026-10-21, #606·#607): 친구 알파 대신 **대표 혼자 여러 판**. 판 수·관문 조건은 PM이 로드맵(`02-roadmap.md` 6장)에 정하고 대표가 확인한다 — 이 양식은 그 수를 따른다.
> 쓰는 법: 한 판이 끝날 때마다(새 계보가 끝나거나 그만둘 때) **아래 "판마다 남길 글"을 복사해** 대표 플레이 이슈 **#608**에 댓글로 붙인다. 한 판에 5분 안쪽. 모든 질문은 건너뛰어도 된다.
> 첫 판 댓글에만 폰 기종·브라우저·설치 여부를 적는다(바뀌면 그때 다시).

## 판마다 남길 글 (복사해서 채움)

```
[판 N]
1. 몇 분 했나요? 새가 몇 번 죽었나요? (계승한 새끼 세대 포함)
2. 이번 판 마지막 새는 왜 죽었나요? 납득됐나요? (예 / 대충 / 아니)
3. 이번 판에 새로 해 본 것 (예: 둥지 옮기기, 2차 번식, 다른 장소)
4. 가장 재밌었던 순간 하나
5. 가장 지루하거나 짜증 났던 순간 하나
6. 다음 판을 또 하고 싶은가요? (1 전혀 ~ 5 꼭)
7. 이상하게 동작한 것 (버튼이 안 눌림, 글자가 잘림, 멈춤 등) — 어디서. 화면 캡처나, 죽은 화면의 "플레이 기록 저장" 파일(wb-run-….jsonl)이 있으면 같이 붙여 주세요
8. 새에 대해 "이건 사실과 다른데?" 싶은 것
9. 자유롭게 한마디
10. 카드 패(뽑힌 카드·결과 확률) 느낌: 납득됨 / 운이 너무 큼 / 잘 모르겠음 — 한 줄
```

첫 판에만 덧붙임:
```
0. 폰 기종 / 브라우저 / 홈 화면에 설치했나요? (예: 갤럭시 S23 / 삼성 인터넷 / 설치함)
   처음 화면에서 뭘 해야 할지 바로 알았나요? (예 / 조금 헤맴 / 많이 헤맴) — 헤맨 곳은?
```

## QA 정리 규칙 (QA용)

- 판마다 `qa/reports/alpha-feedback.md`에 한 줄 표로 옮긴다: 판 번호 · 날짜 · 플레이 분 · 죽은 횟수 · 2·6·10번 답 · 문제 수. 아래에 3·4·5·9번 답을 요약한다(원문 인용은 짧게). 판이 올 때마다 정리한다.
- **흐름 보기**: 판이 쌓이면 6번(또 하고 싶음)과 2번(납득)이 판을 거듭하며 어떻게 바뀌는지, 3번으로 서로 다른 전략을 해 봤는지를 리포트에 적는다 — 혼자 여러 판이라 "처음 느낌"은 1판에만 있다는 점도 적는다.
- **관문 판정**: 로드맵 M3 관문의 판 수(대표 확인, #608)만큼 정리되면 "알파 피드백" 통과. 판 수와 이슈 링크를 리포트 결론에 적는다.
- 7번 문제는 QA가 재현을 시도해 `type:bug` + `sev:` + 담당 부서 라벨로 연다. 재현 정보는 QA가 채운다 — 대표에게 다시 묻지 않는다. 기록 파일이 오면 `npm run sim -- replay`로 먼저 돌린다(`commit`과 `startCommit`이 다르면 배포를 넘은 판이라 리플레이 대상 아님 — 그 커밋에서 화면으로 재현). 재현이 안 되면 그대로 적고 S3 이하로 둔다. 기기·브라우저가 원인이면 그 정보를 꼭 적는다.
- 다른 답은 부서 이슈에 요약해 넘긴다: 0(헤맴) → design(튜토리얼·온보딩)·client · 2·3·4·5·6 → design · 10 → design(#464) · 8 → content · 0(기기별 문제) → client.
- 같은 말이 2판 이상 나오면 리포트에 "반복된 의견"으로 따로 묶는다.
