# 대표 플레이테스트 피드백 양식

> 관리: QA·밸런스. 상태: **v0** (M1, #26). M1 관문 "대표 플레이"의 판정 근거다(02-roadmap 6장 M1).
> 쓰는 법: M1 빌드가 나오면 PM이 `type:human` 이슈를 열고 이 양식을 본문에 붙인다. 대표는 그 이슈에 **댓글로** 답한다. QA가 읽어 정리하고, 버그는 따로 `type:bug` 이슈로 옮긴다.
> 대표의 시간을 아끼려고 짧게 만들었다. 1부만 필수다. 예상 소요: 플레이 60~90분 + 작성 10분.

## 1부. 관문 체크 (필수 — 5개 모두 체크되어야 M1 관문 통과)

```
- [ ] 1. 폰에서 직접 1년 이상 플레이했다 (빨리 감기 없이)
- [ ] 2. 개발용 빨리 감기로 3년차 이후까지 갔다
- [ ] 3. 계승을 1번 이상 했다 (새끼로 갈아타기)
- [ ] 4. 노화 표시를 봤다 (나이가 들어 능력이 떨어진다는 표시)
- [ ] 5. 게임 오버 기록 화면을 봤다
```

체크하지 못한 항목이 있으면 이유를 한 줄로 (예: "계승 화면에서 버튼이 안 눌림").

## 2부. 한 줄 답 (권장 — 아는 만큼만)

1. 직접 플레이한 1년은 대략 몇 분 걸렸나? (목표 40~60분, gdd 4.2)
2. 지루하거나 같은 일을 반복한다고 느낀 때가 있었나? 언제?
3. 뭘 골라야 할지 몰라 헤맨 화면·선택이 있었나?
4. 위험%·예상치를 보고 고르는 게 의미 있게 느껴졌나? (예 / 별로 / 안 봤다)
5. 죽었을 때 왜 죽었는지 납득됐나?
6. 계승할지 말지 고민됐나, 아니면 답이 뻔했나?
7. 생태가 이상해 보인 장면이 있었나? (있으면 생태·콘텐츠가 확인)
8. 또 해 보고 싶은가? (1~5)

## 3부. 문제 (있으면)

문제 하나에 한 줄. 화면 캡처가 있으면 함께 붙인다.

```
- 어디서: (예: 2년차 봄, 둥지 자리 고르기)
- 무엇이: (예: 선택지가 화면 밖으로 잘림)
- 다시 되나: 예 / 아니오 / 모름
```

## QA 정리 규칙 (QA용)

- 1부 결과를 `qa/reports/gate-M1.md`의 "대표 플레이" 칸에 옮긴다(댓글 링크를 근거로).
- 3부 문제는 QA가 재현을 시도해 `type:bug` + `sev:` + 담당 부서 라벨로 연다. 재현 정보(시드·선택 열)는 QA가 채운다 — 대표에게 다시 묻지 않는다. 재현이 안 되면 그대로 적고 S3 이하로 둔다.
- 2부 답은 해당 부서 이슈에 요약해 넘긴다: 1·2·8 → design(결정 예산·반복감), 3·4·6 → design·client, 5 → design, 7 → content.
