# 지표 정의 (계산법)

> 관리: QA·밸런스. 상태: **v1** (M0, #18 · #58). 계산법은 QA 결정(L1), **목표치는 디자인 소유**(기획서 4.5 · 8.3 · 11장, `data/balance/`).
> 목표가 바뀌어도 이 문서의 계산법은 그대로 쓴다. 계산법을 바꾸면 이전 리포트와 비교할 수 없으므로 버전을 올리고 변경 이력에 적는다.

---

## 1. 기본 단위

| 용어 | 정의 |
|---|---|
| **판(run)** | `newRun(config)`부터 게임 오버(조작 중인 개체의 사망)까지. 계승해도 같은 판이다. |
| **표본** | 같은 종 · 같은 봇(버전) · 같은 데이터(커밋)로 돌린 N판. 시드는 `qa-<speciesId>-<botId>-<i>` (i = 1..N). 리포트 사이 비교는 같은 시드 목록으로 한다. |
| **시기 번호** | `(year − 1) × 24 + period` (period 1~24). 판 안의 시간 위치. 단계(step)는 무시한다(해상도 = 반 달). |
| **번식기** | 종 생태 데이터의 `breeding.season.fromPeriod`가 시작되는 시점. 판이 그 시기에 도달했으면(게임 오버 전) "도달한 번식기" 1회. |
| **결정** | 고를 수 있는(`disabled` 아닌) 선택이 **2개 이상**일 때의 `act` 호출 1회. 선택지가 1개뿐인 진행(확인 버튼)은 결정이 아니다. 디자인 명세와 같다(`00-core-loop` 5.1). '옮기기' → 목적지는 결정 2회, 짝이 거절한 지시도 1회(B-6). |
| **목표치** | 종 파일 `data/balance/species/<종>.json`의 `targets`에서 읽는다(아래 표). 허용 범위는 `targets.tolerance`(현재 0.10, #35) — 구간 = 목표 × (1 ± tolerance). 이 문서의 구간 숫자는 tolerance 0.10일 때의 예이고, 데이터가 바뀌면 데이터가 우선한다. |

| `targets` 키 | 지표 |
|---|---|
| `expectedTotalBreeding` | M-01 |
| `avgRunYears` | M-04 |
| `breedingYearRatio` | M-05 |
| `yearBreedingSuccess` | M-06 |
| `firstBroodSuccess` | M-13 |
| `decisionsPerYear` (`min` · `max`) | M-11 |

표기: N = 판 수, T_i = i번째 판의 총 번식 수, x̄ = 평균, s = 표본 표준편차.

## 2. 신뢰구간

- 평균의 95% 신뢰구간: `x̄ ± 1.96 × s / √N`. (N ≥ 1,000에서 정규 근사로 충분하다.)
- 비율의 95% 신뢰구간: `p ± 1.96 × √(p(1−p)/N)`.
- 리포트에는 점추정과 신뢰구간을 함께 쓴다. 예) `4.12 (95% CI 4.03–4.21, N=5,000)`.
- **정밀도 기준**: 관문 판정에 쓰는 평균은 신뢰구간 반폭이 평균의 **2.5% 이하**여야 한다. 기본 N = 5,000(종·봇마다). 총 번식 수의 변동계수가 1을 넘으면 반폭이 2.8%가 되므로 N을 늘린다(필요 N ≈ (1.96 × CV / 0.025)²). 리포트에 실제 반폭을 적는다.

## 3. 지표

### M-01 기대 총 번식 수
- 계산: `E[T] = (Σ T_i) / N`, 95% CI 함께.
- T_i = 게임 오버 시점의 `totalBreeding` (기획서 11.1 — 독립 순간 확정, 미결 점수 없음).
- 목표: `targets.expectedTotalBreeding` ± tolerance → 4.0이면 **[3.6, 4.4]** (02-roadmap 6장 M2).

### M-02 상위 10% 총 번식 수
- 계산: T를 내림차순 정렬해 **위에서 ⌈N/10⌉개의 평균**(상위 10분위 평균).
- 90번째 백분위수를 쓰지 않는 이유: T는 정수라 백분위수가 계단처럼 움직여(예: 9 → 10이면 11% 차이) ±10% 비교가 불안정하다.
- 쓰임: 숙련 봇 공정성(기획서 8.3).

### M-03 종 간 차이
- 계산: 비교하는 종들의 지표값(M-01 또는 M-02) 중 `G = 최댓값 / 최솟값 − 1`.
- 통과: `G ≤ 0.10`. 2종(M4)이든 4종(M5)이든 같은 식 — 어느 두 종을 골라도 10% 이내라는 뜻.
- 각 종의 평균이 2장의 정밀도 기준을 만족해야 판정한다. 못 미치면 "판정 보류"로 쓰고 N을 늘린다.

### M-04 평균 런 길이
- 판 길이(년): `L_i = (게임 오버 시기 번호 − 시작 시기 번호) / 24`.
- 계산: `L̄ = Σ L_i / N`, 95% CI. 분포(중앙값 · 10/90 백분위수 · 히스토그램 1년 단위)도 함께 낸다.
- 목표(기획서 4.5): 평균 봇 박새 ≈4.5 / 꼬마물떼새 ≈5.5 / 저어새 ≈7.5 / 두루미 ≈8.5년, 모두 10년 이하. 무작위 봇 1~3년. 숙련 봇 20년 이상.
- 허용 범위: `targets.avgRunYears` ± tolerance(디자인 #35) → 박새 **[4.05, 4.95]**. 상한 "모두 10년 이하"는 그대로.

### M-05 번식 가능한 해의 비율
- 판마다: `S_i` = 도달한 번식기 수, `E_i` = 그중 번식기 시작 시점에 조작 중인 개체가 **번식 가능 나이**인 번식기 수.
- 계산(합산 비율): `R = Σ E_i / Σ S_i`.
- 번식 가능 여부는 엔진이 로그로 알려 준다(봇 인터페이스 요구, #19). QA가 나이로 추정하지 않는다.

### M-06 번식 가능한 해의 기대 번식 성공
- 계산(합산 비율): `B = Σ T_i / Σ E_i`.

**분해 항등식** (기획서 8.3의 식을 측정 가능한 형태로):
```
E[T] = (Σ S_i / N) × R × B          ← 정확히 성립
       ‾‾‾‾‾‾‾‾‾‾‾
       판당 도달한 번식기 수 (≈ 평균 런 길이)
```
- 리포트는 이 세 항을 종별로 나란히 보여 준다. 목표에서 벗어나면 어느 항 때문인지 바로 보인다.
- 판당 도달한 번식기 수는 평균 런 길이와 비슷하지만 같지 않다(시작 시기, 번식기 직전 사망). 둘 다 적는다.

### M-07 계승 주기
- 판마다: 계승 횟수 `H_i`, 개체별 **재임 기간**(그 개체를 조작한 연수 = 계승 또는 사망 시기 − 넘겨받은 시기, /24).
- 계산: 판당 평균 계승 횟수 `Σ H_i / N`, 재임 기간의 평균 · 중앙값(모든 판의 모든 개체를 모아서).
- 추가: **계승 직후 사망률** = 계승으로 넘겨받은 개체 중 첫 번식기 전에 죽은 비율(비율 CI). 계승의 위험(첫 겨울·미성숙기)이 의도대로인지 본다.

### M-08 사망 원인 분포
- 게임 오버를 일으킨 사망 로그의 `cause`별 판 비율(비율 CI).
- 함께: 원인 × 사망 시기(계절) 교차표, 원인 × 개체 나이 구간(번식 전 / 노화 전 / 노화 후).
- `cause` 코드는 5개로 확정(`00-core-loop` 8장, #35): `starvation` / `predation`(이벤트가 포식자를 지목하면 `predation:<predatorId>`) / `cold` / `accident` / `disease`. 집계는 5개 단위로 하고, `predation`은 포식자 id별로 한 번 더 나눈다.
- 노화·번식 후 고갈은 원인 코드가 아니다. "노화 후 `starvation`"처럼 나이 구간 교차표로 본다.

### M-09 이벤트별 사망 기여도
- 사망 로그가 이벤트 처리 단계에서 나왔으면 그 이벤트 id에 1을 더한다.
- 계산: 이벤트 id별 `사망 수 / 그 이벤트 발생 수`(치명률)와 `사망 수 / 전체 게임 오버 수`(기여율).
- 치명률이 다른 이벤트보다 두드러지게 높은 것을 리포트 위쪽에 둔다(판정은 디자인).

### M-10 선택 분포
- `Choice.kind`별로 고른 선택(`id`)의 빈도 비율. 결정(1장)만 센다.
- 산란수(`clutchSize`)는 고른 값의 분포, 계승(`inheritance`)은 계승/잔류 비율.
- 쓰임: 봇이 실제로 다양한 선택을 하는지, 한 선택이 압도적인지(지배 전략의 신호).

### M-11 1년 결정 수
- 판 안의 **완전한 해**(그 해 1~24시기를 모두 지난 해)마다 결정 수를 센다. 게임 오버가 난 해는 빼고, 판의 첫 해는 시작 시기부터 24시기를 지난 경우만 넣는다.
- 계산: 완전한 해 전체의 평균 · 10/90 백분위수. 번식에 성공한 해와 아닌 해를 나눠서도 낸다.
- 목표: 평균 봇 평균이 `targets.decisionsPerYear` 안 → **[60, 90]**(기획서 4.2).
- **60 미만인 해의 비율**(`00-core-loop` 5.3): 완전한 해 중 결정 수 < `decisionsPerYear.min`인 해의 비율(비율 CI). 목표 **≤ 5%**. 번식을 완전히 포기한 해(약 56결정, 5.2)가 연달아 나오는지 보려고, 그런 해가 같은 판에서 2년 연속인 판의 수도 함께 적는다.
- **결정 종류별 비중**(5.3): 결정을 `Choice.kind`로 나눈 비율. 목표 **행동 결정 60~70%**. 행동 결정 = `kind: action` + `kind: node`(옮기기 목적지) — 디자인 5.2 설계값(71결정 중 행동 38 + 목적지 9 = 66%)과 같은 기준. 잠정(#58): 목적지를 행동 결정에 넣는 해석은 디자인 확인 대기.

### M-12 지배 전략 검사
- 고정 전략 봇 F = 평균 봇에서 **한 종류의 결정만** 상수 규칙으로 바꾼 봇. M2 기본 목록:

| 고정 전략 | 바꾸는 결정 | 규칙 |
|---|---|---|
| 항상 최대 산란 / 항상 최소 산란 | `clutchSize` | 고를 수 있는 최댓값 / 최솟값 (기획서 8.3) |
| 항상 잔류 / 가능하면 항상 계승 | `inheritance` | 늘 잔류 / 늘 계승(새끼는 평균 봇 규칙으로 고름) (QA 임무 7장) |
| 항상 2차 번식 / 2차 번식 안 함 | 2차 번식 여부 관문 | 열리면 늘 '한다' / 늘 '안 한다' (#35, `00-core-loop` 6.2) |
| 항상 가장 안전한 장소 | `node`(옮기기 목적지) | 평균 봇이 옮기기를 골랐을 때 목적지는 `preview.deathRisk`가 가장 낮은 곳(같으면 목록 앞쪽) (#35) |
| 옮기기 안 함 | `action` 중 `move` | `move`를 고르지 않는다. 평균 봇이 `move`를 골랐을 자리에서는 남은 행동 중 평균 봇의 다음 순위 (#35 — 먹이 터 고갈 규칙이 머물기를 지배 전략에서 막는지) |

- 짝 지시·급이 강도 관련 고정 전략은 `04-breeding`(M1)이 나오면 디자인이 추가를 요청한다.
- 계산: 같은 종 · 같은 시드 목록 · 같은 N으로 M-01을 잰다.
- **실패**: 어떤 F의 E[T]가 숙련 봇 E[T] 이상(점추정). **경고**: F가 평균 봇보다 신뢰구간이 겹치지 않게 높다(평균 봇 규칙이 그 결정에서 나쁘다는 뜻 — 봇을 고치거나 수치를 본다).
- 전제: 숙련 봇이 평균 봇보다 확실히 높아야 의미가 있다. 숙련 봇 E[T]의 CI 하한이 평균 봇 E[T]의 CI 상한보다 낮으면 "판정 보류 — 숙련 봇 보강".

### M-13 1차 번식 성공률
- 판마다 그 해 조작 개체의 **첫 번식 시도**(`breeding` 시도 시작 로그 중 그 해 첫 것)를 모으고, 그중 성공(독립 확정) 비율. 2차·대체 번식은 넣지 않는다(합산 비율, 비율 CI).
- 목표: `targets.firstBroodSuccess`(박새 0.55, `01-formulas` 9장 보정 근거). 관문 조건은 아니고, M-01이 벗어났을 때 원인을 찾는 진단 지표다.

### M-14 1년 최대 초과
- 한 해(시기 1~24)의 번식 성공 수가 종별 1년 최대(`02-scoring` 3장: 박새 2, 나머지 1)를 넘은 해의 수.
- 목표: **0건**. 1건이라도 있으면 `test-strategy.md` 2장 불변식 7 위반 = 오류 판이다(지표가 아니라 버그로 보고).

## 4. 리포트에 반드시 적는 것

```
- 날짜:
- 게임 버전 · 커밋: (데이터 버전은 따로 두지 않으므로 커밋이 데이터 버전이다 — 03-contracts 6장)
- 종 / 봇 · 봇 버전 / N / 시드 목록 규칙:
- 실행 명령:
- 오류 판 수(불변식 위반 · 예외, test-strategy 2장): 0이 아니면 지표보다 먼저 쓴다
```

## 5. 측정에 필요한 엔진 출력

위 지표를 계산하려면 시뮬레이터가 판마다 아래를 내야 한다. 엔진 요구 이슈(#19)로 보낸다.
- 판 설정(종 · 시드 · 봇), 선택 열(choiceId 순서), 최종 `totalBreeding`
- 시기 번호가 붙은 로그: 번식기 시작(번식 가능 여부 포함), 번식 시도 · 성공, 계승, 사망(`cause` 코드 · 이벤트 id), 결정 여부(고를 수 있는 선택 수)
