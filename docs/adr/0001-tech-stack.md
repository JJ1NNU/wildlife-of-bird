# ADR 0001: 기술 스택

- 상태: 채택
- 날짜: 2026-10-03
- 결정 부서: engine
- 리뷰: 부트스트랩 예외로 머지 후 리뷰 (01-collaboration 8장) — client · design · content · qa

## 맥락

전 부서가 이 결정을 기다린다(#2). 조건은 `docs/agents/engine.md` 8장과 gdd 13.1장이다.

- 모바일 세로 화면 **웹 게임 + PWA**(설치·오프라인), **무료 정적 호스팅**
- **엔진은 UI와 분리**되어 Node에서도 돈다(시뮬레이터). 순수 함수 + 시드 고정 난수
- 엔진·화면·시뮬레이터·데이터 검증이 **같은 타입 정의를 공유**하면 좋다
- UI는 카드·메뉴·지도·슬라이더 중심. 실시간 물리·대량 스프라이트 없음
- **대표는 게임 개발 초보**(웹사이트 제작 경험 있음) → 주류 도구, 적은 의존성, 좋은 문서
- 허용적 라이선스만(MIT · Apache-2.0 · BSD)
- 모바일 화면 자동 테스트 가능

## 선택지

### 언어 · UI 틀

| 선택지 | 장점 | 단점 |
|---|---|---|
| **TS + React + Vite** | 가장 주류 — 문서·예제·질문 답이 압도적으로 많다. 카드·메뉴 UI에 충분. 대표가 막혔을 때 검색으로 풀 확률이 가장 높다 | 번들이 Svelte보다 크다(이 게임 규모에서는 문제되지 않는다) |
| TS + Svelte + Vite | 코드가 짧고 번들이 작다 | 자료가 React보다 적다. 대표가 혼자 고칠 때 불리하다 |
| TS + Phaser + DOM UI | 게임 엔진의 편의 | 실시간 물리·스프라이트가 없는 이 게임에는 과하다. 틀 하나가 더 늘어난다 |

### 패키지 구조

| 선택지 | 장점 | 단점 |
|---|---|---|
| **npm workspaces** | Node에 이미 들어 있다 — 설치할 도구가 없다. 대표의 환경에서 바로 된다 | pnpm보다 설치가 느리고 디스크를 더 쓴다 |
| pnpm workspaces | 빠르고 엄격하다 | 대표가 도구를 하나 더 설치해야 한다 |
| 단일 패키지 | 가장 단순 | 엔진에 UI가 섞여 들어가는 것을 막을 장치가 없다(원칙 3 위반을 기계가 잡지 못한다) |

### 빌드

| 선택지 | 장점 | 단점 |
|---|---|---|
| **빌드 없음 — Node가 TS를 그대로 실행** | 명령이 짧다(`node packages/sim/src/cli/run-sim.ts`). 빌드 산출물·감시 모드가 없어 막힐 곳이 적다 | Node 22.18+ 필요. `enum`·생성자 매개변수 속성을 못 쓴다(`erasableSyntaxOnly`로 기계가 막는다) |
| tsc 빌드 + 프로젝트 참조 | 전통적 | 화면 개발 중 `tsc -b --watch`를 같이 띄워야 한다. 초보에게 단계가 하나 더 |

> 검증: `npm workspaces`가 만든 심링크를 Node가 realpath로 풀기 때문에,
> 패키지 간 `@wb/engine` 가져오기도 타입 제거가 그대로 동작한다(실험으로 확인).

### 나머지

| 자리 | 고름 | 왜 |
|---|---|---|
| 테스트 | **Vitest** | Vite와 같은 집안이라 설정이 하나로 끝난다. TS를 그대로 읽는다. MIT |
| 린트 + 포맷 | **Biome** | 두 일을 도구 **하나**가 한다. 의존성 1개(ESLint + typescript-eslint + Prettier는 수십 개). MIT |
| 데이터 검증 | **Zod** | 스키마 하나에서 타입과 검증기가 같이 나온다(같은 형식을 두 번 적지 않는다). 실패 위치(`path`)를 주므로 "파일·필드·이유" 요구를 채운다. 한국어 메시지 내장. MIT |
| e2e | Playwright (**지금 설치하지 않는다**) | `apps/web`이 생기는 M1~M3에 client·qa가 넣는다. 15장: 안 쓰는 도구를 미리 넣지 않는다 |

## 결정

**TypeScript(strict) + npm workspaces 모노레포 + 빌드 없는 실행**, 화면은 **React + Vite**,
검사는 **Biome · Vitest · Zod**.

```
packages/schema   데이터 타입 · 검증기 (Zod)
packages/engine   게임 규칙 (순수 · 결정론) — @wb/schema만 의존
packages/sim      헤드리스 러너 · 봇 인터페이스
apps/web          화면 (React + Vite) — client 부서가 #17에서 만든다
```

- 패키지는 **소스를 그대로** 내보낸다(`exports: "./src/index.ts"`). Vite와 Node가 둘 다 읽는다.
- `packages/engine`은 `@wb/schema` 말고 아무것도 의존하지 않는다 —
  UI 라이브러리가 엔진에 들어가는 것을 `package.json`으로 막는다(품질 기준).
- 난수는 **SplitMix32**: 32비트 정수 하나가 전체 상태여서 저장 파일에 숫자 한 개로 들어가고,
  저장·불러오기를 왕복해도 수열이 이어진다. `Math.random`과 현재 시간은 쓰지 않는다.
- Node **22.18 이상**(CI는 24). 타입 제거 실행의 전제다.

### 성능 목표 (측정해서 못 미칠 때만 최적화한다)

박새 평균 런 ≈4.5년(gdd 4.5장), 평시 1시기 = 1단계이므로 한 판 ≈300단계.

- **박새 1만 판**(평균 플레이어 봇, 단일 코어): **5분 이내**
- `preview` 한 번: 1ms 이내 (화면이 선택마다 부른다)

M2에 측정한다. 못 미치면 먼저 **시드별 샤딩**(`node:child_process`로 코어 수만큼 나눠
실행)으로 푼다 — 엔진이 순수 함수이므로 공유 상태가 없다. 워커 스레드·WASM은 샤딩으로도
안 될 때 ADR로 다시 정한다. 지금은 만들지 않는다(15장).

## 결과

- **좋아지는 것**
  - 설치할 도구가 Node 하나다. 빌드 산출물이 없어 "왜 안 바뀌지" 같은 막힘이 없다.
  - 엔진·화면·시뮬레이터·검증기가 같은 타입을 쓴다. 데이터 형식을 한 곳에만 적는다.
  - 런타임 의존성이 **Zod 하나**다(화면의 React 제외). 개발 의존성은 4개.
- **감수하는 것**
  - Node 22.18+ 를 요구한다. 그보다 낮은 Node에서는 명령이 돌지 않는다.
  - `enum`과 생성자 매개변수 속성을 쓸 수 없다(`erasableSyntaxOnly`가 막는다). 유니온 타입으로 대신한다.
  - Biome는 ESLint보다 자료가 적다. 규칙은 `recommended` 기본만 쓰고 늘리지 않는다.
  - npm install이 pnpm보다 느리다.
- **다른 부서가 해야 할 일**
  - client: `apps/web`을 React + Vite로 만든다(#17). 호스팅·리더보드는 ADR-002(#16).
    엔진은 `npm run build` 같은 빌드 산출물을 내지 않으므로 Vite가 `@wb/engine` 소스를 직접 읽는다.
  - design · content: 스키마 v0에 맞춰 데이터 파일을 쓴다. 형식은 `packages/schema/README.md`.
  - qa: 봇은 `Bot` 인터페이스로 쓴다(`packages/sim/README.md`). e2e 도구는 `apps/web` 이후.
  - 전 부서: 머지 후 리뷰 이슈에 의견을 단다. 필요하면 엔진이 ADR을 개정한다.
