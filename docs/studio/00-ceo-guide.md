# 대표 운영 가이드

> 대표(사용자)님을 위한 문서입니다. 에이전트들은 읽지 않아도 됩니다.

## 1. 대표님이 하시는 일

| 일 | 언제 | 예상 시간 |
|---|---|---|
| 에이전트 세션 실행 (라운드 운영) | 원하실 때. 하루 1라운드면 충분 | 실행만 하면 됨 |
| "📋 대표 보고" 이슈 읽기 | 라운드 끝 | 3분 |
| `needs:ceo` 이슈에 답하기 (결정) | 보고에 올라올 때 | 건당 1~5분 |
| `type:human` 이슈 처리 (이미지 생성, 계정 만들기, 비밀값 설정, 전문가 검수 의뢰) | 보고에 올라올 때 | 이미지 배치 1개 30분~1시간 |
| 플레이테스트 | 마일스톤 관문마다 | 30분~1시간 (M1은 약 1시간) |
| 관문 승인 · 출시 승인 | 마일스톤 끝 | 5분 |

나머지는 에이전트들이 알아서 합니다. 일의 내용에 직접 손대실 필요는 없습니다.

## 2. 처음 한 번: 준비

1. **GitHub 저장소 만들기**: 새 저장소(비공개 권장, 공개 여부는 출시 때 결정).
2. **이 폴더 내용 올리기**
   ```bash
   cd wild-bird-studio
   git init -b main
   git add .
   git commit -m "[pm] 스튜디오 초기 구성"
   git remote add origin https://github.com/<계정>/<저장소>.git
   git push -u origin main
   ```
3. **Claude Code에서 이 저장소로 세션을 열 수 있는지 확인**합니다(클라우드 세션 또는 내 컴퓨터에서 저장소를 내려받아 실행).
4. **GitHub CLI(gh) 인증**: 내 컴퓨터에서 실행한다면 `gh auth login`. 클라우드 세션은 PM이 첫 근무에서 확인하고, 안 되면 알려 드립니다.
   - 저장소의 main 브랜치 보호 설정에서 "승인 필요(Require approvals)"는 켜지 마세요. 모든 에이전트가 같은 계정을 써서 서로 승인할 수 없습니다(승인은 댓글·라벨로 대신합니다).
5. **PM 첫 근무 실행**(아래 실행 프롬프트). 라벨·마일스톤·첫 이슈들이 만들어집니다.
6. **이미지 생성 도구 준비**: 쓰실 도구의 이용약관이 결과물을 웹에 올려 친구들과 공유하는 용도를 허용하는지 확인해 주세요.

## 3. 에이전트 실행 프롬프트

각 부서는 **별도 세션**으로 실행합니다. 세션을 열고 아래 문장을 그대로 붙여 넣으세요.

공통 형식
```
너는 「야생조류 키우기」 스튜디오의 [부서명] 부서 에이전트야.
CLAUDE.md와 docs/agents/[slug].md를 읽고 근무 사이클을 1회 수행해.
```

| 부서 | 붙여 넣을 문장 |
|---|---|
| PM (라운드 시작) | `너는 「야생조류 키우기」 스튜디오의 PM 부서 에이전트야. CLAUDE.md와 docs/agents/pm.md를 읽고 '라운드 시작 근무'를 수행해.` |
| PM (라운드 끝) | `너는 「야생조류 키우기」 스튜디오의 PM 부서 에이전트야. CLAUDE.md와 docs/agents/pm.md를 읽고 '라운드 끝 근무'를 수행해.` |
| 게임디자인 | `너는 「야생조류 키우기」 스튜디오의 게임디자인 부서 에이전트야. CLAUDE.md와 docs/agents/design.md를 읽고 근무 사이클을 1회 수행해.` |
| 생태·콘텐츠 | `너는 「야생조류 키우기」 스튜디오의 생태·콘텐츠 부서 에이전트야. CLAUDE.md와 docs/agents/content.md를 읽고 근무 사이클을 1회 수행해.` |
| 엔진 | `너는 「야생조류 키우기」 스튜디오의 엔진 부서 에이전트야. CLAUDE.md와 docs/agents/engine.md를 읽고 근무 사이클을 1회 수행해.` |
| 클라이언트·배포 | `너는 「야생조류 키우기」 스튜디오의 클라이언트·배포 부서 에이전트야. CLAUDE.md와 docs/agents/client.md를 읽고 근무 사이클을 1회 수행해.` |
| 아트·UX | `너는 「야생조류 키우기」 스튜디오의 아트·UX 부서 에이전트야. CLAUDE.md와 docs/agents/art.md를 읽고 근무 사이클을 1회 수행해.` |
| QA·밸런스 | `너는 「야생조류 키우기」 스튜디오의 QA·밸런스 부서 에이전트야. CLAUDE.md와 docs/agents/qa.md를 읽고 근무 사이클을 1회 수행해.` |

특정 일을 시키고 싶으시면 뒤에 덧붙이세요. 예) `…수행해. 이번엔 #23 이슈부터 처리해.`
PM에게 정해진 근무 대신 특정 일만 시키면 '임시 근무'가 되어 라운드 기록이 꼬이지 않습니다.

### 동시에 여러 부서를 돌릴 때
- 부서마다 다른 세션을 씁니다. **같은 부서를 두 세션에서 동시에 돌리지 마세요.**
- 내 컴퓨터 한 곳에서 여러 세션을 돌린다면 부서별 작업 폴더를 따로 만드세요.
  ```bash
  git worktree add --detach ../wb-engine main   # 엔진용 폴더
  git worktree add --detach ../wb-design main   # 디자인용 폴더
  ```

## 4. 라운드 운영 (권장 순서)

**M0 첫 라운드** (순서가 중요합니다)
1. PM (라운드 시작) — 라벨·마일스톤·이슈 만들기
2. 엔진 — 기술 스택 결정(ADR-001)과 저장소 뼈대. 다른 부서의 전제입니다
3. 게임디자인 · 생태·콘텐츠 · 아트·UX — 동시에
4. 클라이언트·배포 — 엔진 뼈대 위에 웹 골격과 배포
5. QA·밸런스
6. PM (라운드 끝) — 마무리 보고

**이후 라운드**
1. PM (라운드 시작) — 작업 분배
2. 게임디자인 · 생태·콘텐츠 · 엔진 · 클라이언트·배포 · 아트·UX (동시에)
3. QA·밸런스
4. PM (라운드 끝) — 대표 보고

한 라운드에 모든 부서를 꼭 돌릴 필요는 없습니다. PM 보고의 "다음 라운드 실행 순서"를 따르시면 됩니다.

## 5. 결정 답하기 (`needs:ceo`)

이슈 첫 줄에 추천안이 있습니다. 댓글로 답하시면 됩니다.
- `추천안대로` — 가장 흔한 답
- `B로` / `둘 다 아니고 ○○로`
- `보류, 이유: …`

## 6. 이미지 생성하기 (`type:human`, 아트·UX 요청)

1. 이슈 `[art→대표] 이미지 생성 배치 NN`을 엽니다. 에셋 ID, 복붙용 프롬프트, 크기, 후보 수, 파일명이 표로 있습니다.
2. 이미지 생성 도구에 프롬프트를 붙여 후보를 만듭니다.
3. 결과를 `assets/inbox/batch-NN/` 폴더에 지정된 파일명·형식(WebP 또는 JPG, 긴 변 1024px 이하)으로 올립니다. git으로 푸시하거나, GitHub 웹에서 폴더를 열고 "Add file → Upload files"로 main에 바로 올리셔도 됩니다. 이슈 첨부는 쓰지 마세요(에이전트가 내려받지 못할 수 있습니다).
4. 이슈에 `완료 — 사용 도구: ○○` 댓글.
5. 아트가 고르고, 생태·콘텐츠가 새의 생김새를 검토하고, 틀린 것은 고친 프롬프트로 다음 배치에 다시 요청합니다.

## 7. 플레이테스트

관문마다 PM이 미리보기 주소와 확인할 점을 보냅니다. M1은 박새 1년을 직접 플레이하고(약 1시간), 3년차 이후는 개발용 빨리 감기로 확인합니다. 휴대폰으로 플레이하고 피드백 양식(QA가 준비)에 적어 주세요. 친구 알파(M3)·베타(M6)는 PM이 친구용 안내문까지 만듭니다.

## 8. 문제가 생겼을 때

| 상황 | 하실 일 |
|---|---|
| 에이전트가 남의 영역을 고쳤다 | PR에 `수정 요청 (대표): 소유권 위반` 댓글 → PM이 정리 |
| 같은 문제로 계속 맴돈다 | 세션을 끝내고 PM 세션에 "#이슈 상황 정리해 줘" |
| 문서끼리 내용이 다르다 | PM에게 이슈. 우선순위: 대표의 최신 결정 > 기획서 > 계약·ADR > 로드맵 > 임무 문서 |
| main의 CI가 깨져 있다 | 엔진 세션 실행(규칙상 최우선으로 고칩니다) |
| 아무도 할 일이 없다고 한다 | PM 세션 실행 — 다음 일을 만들어 줍니다 |

## 9. 나중에

라운드 운영이 안정되면 부서별 근무를 정해진 시간에 자동으로 실행하도록 설정하는 것도 검토할 수 있습니다.
