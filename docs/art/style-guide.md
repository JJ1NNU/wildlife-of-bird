## 1. 화풍 — **A 담색 수채 생태도감** (확정, D-015)

대표 결정 2026-10-04(#71). 고른 근거와 테스트 9장은 `style-options.md` 1·6장.

### 1.1 한 줄 정의
**종이 흰빛 위의 맑은 수채 담채 + 식별 특징을 잡아 주는 가는 잉크 선.** 조류 도감 그림처럼 차분하고 정확하게. 그림의 첫 임무는 "어떤 새인지 알아보게 하는 것"이다.

| 분류 | 이렇게 |
|---|---|
| `bird` `pred` | 펜선으로 윤곽과 식별 무늬(뺨·턱·세로줄·날개 띠·부리 모양)를 또렷하게. 칠은 평평한 담채 1~2겹. 배경은 **종이색 단색**(아래 `paper`) — 배경 제거 없이 카드에 그대로 얹힌다 |
| `bg` | 같은 수채지만 **윤곽선을 더 흐리고 가늘게**, 원경은 공기 원근으로 옅게(시안 C에서 빌린 것). 아래 절반은 디테일을 줄인다(UI 자리, 용량) |
| `scene` | 장면의 긴장은 그림이 아니라 **배경 명도(어둡게) + UI의 경고색·아이콘**으로 만든다. 피·과장된 송곳니·붉은 눈 없음 |
| UI | 화풍과 별개로 **평면 벡터**(아이콘·카드·게이지). 화면은 [그림 레이어] + [UI 레이어] 두 겹 |

### 1.2 색 팔레트
그림 프롬프트의 색 단어와 UI 토큰(`packages/tokens`)이 같은 이름을 쓴다.

| 이름 | 값 | 그림에서 | UI 토큰 |
|---|---|---|---|
| paper (종이색) | #FAF8F2 | 새·포식자의 단색 배경, 하늘 | `--wb-color-paper` |
| sage green | #8BA68C | 잎·풀 | `--wb-color-sage` (글자 쓰려면 `sage-strong` #3F6B4A) |
| warm ochre | #D3A15A | 흙·나무껍질·마른 잎 | `--wb-color-ochre` (`ochre-strong` #7E5410) |
| slate grey | #7A8894 | 그림자·바위·물 | `--wb-color-slate` (`slate-strong` #3E4A54) |
| ink | #1F2421 | 펜선 | `--wb-color-ink` |

새 자체의 색은 팔레트에 맞추지 않는다 — **종의 실제 색이 우선**(콘텐츠 `field-marks.md`). 팔레트는 배경·환경에만 강제한다.

### 1.3 프롬프트 공통 블록 (모든 그림 프롬프트의 맨 앞)
```
watercolor field guide illustration, light flat washes with thin dark ink outlines, muted natural palette of sage green, warm ochre, slate grey and paper off-white, soft even daylight, no texture noise, clean composition, no text, no border, no signature, no watermark
```
분류별 꼬리 블록(공통 블록 뒤, 대상 설명 앞에 붙인다):

| 분류 | 꼬리 블록 |
|---|---|
| `bird` `pred` | `single animal only, strict side profile facing left, whole body visible, plain flat paper off-white background with nothing else, square format` |
| `bg` | `no animals, no birds, no people, no buildings, softer and fainter outlines than a field guide plate, hazy pale distance, fewer fine details in the lower half, square format` |
| `scene` | `no blood, no exaggerated fangs, no glowing eyes, no people, square format` |

### 1.4 배치 01에서 배운 것 (프롬프트·검수 규칙)
1. **비율 지시는 무시된다**(Gemini Pro 3.1, 4:5 → 1:1). 모든 그림을 **1:1로 받는다.** 세로 `scene`은 1:1에서 가운데 가로 80%를 남기고 잘라 4:5로 만든다 → 구도 지시에 "주인공은 가운데 80% 안에".
2. **박새류를 노란 배의 유럽 박새로 끌고 간다.** 새 프롬프트에는 `field-marks.md`의 특징 + "생성 AI가 틀리기 쉬운 특징"을 부정어로 넣는다(예: `white belly, not yellow, not buff`). 검수 때 이 특징부터 본다.
3. **오른쪽 아래 생성 도구 표시**가 모든 그림에 남는다(`no watermark`로 안 사라질 수 있음). 후처리에서 지운다(5장).
4. **배경 용량**: 가는 선이 많은 숲이 1024px·품질 85에서 249KB(예산 한계). → 꼬리 블록의 `fewer fine details in the lower half` + 5장 압축 규칙.
5. 일관성(배치마다 같은 화풍이 나오는가)은 아직 검증 전이다 — **박새 첫 배치(#25)는 에셋당 후보 2장**을 받아 본다.

### 1.5 금지 표현 (그림)
- 그라데이션 하늘·역광 번짐·강한 명암 대비(시안 C 쪽으로 미끄러지는 것), 두꺼운 만화 윤곽선·단색 면만으로 된 그림(시안 B 쪽)
- 의인화(옷·표정·사람 같은 자세), 귀여움 과장(큰 눈·짧은 다리), 화면 안 글자
- 새를 배경 그림에 넣기(`bg`는 새 없이, 화면에서 합성)
- 7장 금지 사항 전부

## 3. 글자·대비·터치 (화풍과 무관, 반드시)

- 글자 대비 **WCAG AA**: 본문 4.5:1, 18px 이상 굵은 글자 3:1. 그림 위의 글자는 반투명 판 또는 단색 띠 위에 올린다.
- 터치 영역 **44×44px 이상**. 인접 터치 영역 사이 간격 8px 이상.
- 세로 한 손 조작. **360×640 ~ 430×932에서 가로 스크롤이 없어야 한다.**
- 폰트는 **OFL 등 자유 사용 라이선스만**. 한글 글립이 있어야 한다. 구체 선정은 디자인 토큰(#15).
- 색만으로 정보를 전하지 않는다 — 위험·확률은 색 + 아이콘 + 숫자를 함께 쓴다(gdd 3장 원칙 5).

## 5. 후처리 (v1)

### 5.1 도구
| 일 | 도구 | 라이선스 | 어디서 |
|---|---|---|---|
| 크기 변환 · 자르기 · WebP 압축 · 생성 도구 표시 지우기 · 비교 시트 | **Pillow** (Python) | HPND(허용형) | 대표 PC에 이미 있다(12.3, 2026-10-03 확인). 배치 01 시트를 실제로 만들었다 |
| SVG 렌더·검수(와이어프레임·실루엣·아이콘) | **Chrome headless** | — | 대표 PC |
| 배경 처리 | **하지 않는다** — 아래 5.3 | | |
| 그림 생성 | **대표**가 이미지 생성 AI로(D-025, #264). 아트는 프롬프트·선별·후처리 — `docs/agents/art.md` 7장 | 생성 도구 약관 | 대표 PC |

- 후처리는 **아트가 대표 PC에서 돌리는 오프라인 작업**이다. 결과물(WebP·SVG)만 저장소에 들어간다. 그래서 Pillow는 **저장소 의존성이 아니다**(`package.json`·CI에 넣지 않는다). 엔진 스택(Node)에 넣어야 할 이유가 생기면 그때 `sharp`(Apache-2.0)로 옮기고 `review:engine`.
- 스크립트는 첫 실제 에셋 처리 때(M1 박새 배치) `scripts/art/`에 만든다. 그 전에는 만들지 않는다(01-collaboration 15장).

### 5.2 처리 순서 (모든 생성 그림)
1. **표시 지우기**: 오른쪽 아래 생성 도구 표시. `bird` `pred`는 단색 배경이므로 그 자리를 `paper`색으로 칠한다. `bg` `scene`은 가장자리 12%를 잘라 낸다(1:1 → 가운데 88% 정사각형).
2. **자르기**: `scene`은 1:1 → 4:5(1.4장). `bird`는 2장 구도 규칙(몸길이 비율·발끝 92%)에 맞게 캔버스 위치 조정.
3. **크기**: 4장 표의 최종 긴 변으로.
4. **압축**: WebP 품질 **80**에서 시작, 상한을 넘으면 4장 규칙대로 크기를 먼저 줄인다.
5. 저장: `assets/<분류>/<ID>.webp`, `asset-list.md`에 출처 기록(6장).

### 5.3 배경 처리는 하지 않는다
`bird` `pred`는 **종이색(#FAF8F2) 단색 배경**으로 받고, 화면이 그 색을 그대로 쓴다 — 카드·패널 바탕 = 그림 배경색(`--wb-color-paper`). 배치 01에서 A의 새 그림은 실제로 단색 종이 배경으로 나왔다.
새가 배경 그림 위에 겹치는 자리(메인 턴)는 **새를 종이색 카드 안에 둔다** — 알파를 만들지 않는다. 이걸로 안 되는 화면이 생기면 그때 한 색 빼기(Pillow)를 시험하고 이 장을 고친다.

### 5.4 허용 라이선스 (저장소에 들어오는 그림·글꼴·소리)
| 무엇 | 허용 | 금지 |

| 그림 | 대표가 생성한 이미지(도구 이름 기록), 아트가 직접 만든 SVG, CC0 | 출처 불명 이미지, 사진·남의 그림 따라 그리기, CC BY-NC · BY-ND |

## 7. 금지

- 프롬프트에 **실존 작가 이름**을 쓰지 않는다. 사진이나 특정 그림을 따라 그리게 하지 않는다.
- 콘텐츠의 생태 검토를 통과하지 않은 새·포식자 그림을 **최종 에셋으로 쓰지 않는다**(자리표시·화풍 테스트는 예외).
- gdd 12장 생태 오류 체크리스트를 그림으로 저지르지 않는다 — 특히 **레벨업=몸집 성장**(새는 성체 크기에서 더 자라지 않는다. 성장은 깃·자세·행동으로 표현한다), **포식자=악당**(포식자도 새끼를 먹이는 생태계 구성원으로 그린다. 과장된 송곳니·붉은 눈 금지).
