# 에셋 목록 v0

> 소유: 아트·UX. 1.0까지 필요한 그림·UI 에셋과 우선순위. ID 규칙은 `docs/studio/03-contracts.md` 5장, 형식·용량은 `style-guide.md` 4장.
> **v0은 "무엇이 필요한가"의 목록이다.** 개수는 기획(이벤트·장소 데이터)이 늘면 바뀐다. 이미지 요청은 현재·다음 마일스톤 것만 낸다(art.md 2장).

## 0. 읽는 법

- **상태**: `필요` → `요청됨`(배치 이슈) → `생성됨`(inbox) → `검수중`(콘텐츠 생태 검토) → `완료`
- **M**: 그 에셋이 화면에 처음 필요한 마일스톤. 그 전까지는 자리표시(`ph.*`)로 개발한다.
- **출처**: 완료된 에셋은 도구·모델·날짜·프롬프트 파일을 적는다(`style-guide.md` 6장). 비어 있으면 완료가 아니다.
- 새 그림은 콘텐츠의 생태 검토를 통과해야 `완료`(gdd 2장 21).

- 옆모습·왼쪽 향함, 200×200 캔버스, **몸길이 비율은 종끼리 고정**(`style-guide.md` 2장: 0.35 / 0.40 / 0.80 / 0.92), 발끝 92% — 최종 그림과 같은 틀이라 교체해도 화면이 흔들리지 않는다.
- 한 색(#7A8894 = 토큰 `--wb-color-slate`). 식별 무늬는 넣지 않았다 — 실루엣으로 종 구분만.
- 박새는 캔버스 안에서 작다(비율 0.35). 목록·가계도처럼 작은 자리에서 크게 보여야 하면 클라이언트가 그 자리에서만 `viewBox`를 잘라 쓴다(예: 박새 `55 120 90 70`). 종끼리 크기를 비교하는 화면(도감)에서는 그대로.
- 포식자·배경 자리표시는 만들지 않는다 — 지금 쓰는 화면이 없다. M1 이벤트 화면이 필요로 하면 그때.
