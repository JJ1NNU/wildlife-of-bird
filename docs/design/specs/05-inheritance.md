## 2. 런 시작 개체 — 화면 S-03

모든 종은 '첫 번식기를 앞둔 젊은 성조'로 시작한다(gdd 4.1). 박새: `species.runStart`(나이 1, `period 1`, 장소 `forest-edge`).

| 항목 | 값 |
|---|---|
| 성별 | **플레이어가 고른다**(S-03, ♀ / ♂). `RunConfig.startSex`. 결정 예산(`00-core-loop` 5장)에는 넣지 않는다 — 런마다 1번 |
| 잠재력[s] | `stats.aptitudeMean[species.aptitude[s]]` — **종 평균 그대로**. 난수 없음 |
| 현재값[s] | `잠재력[s] × mate.candidateCurrentRatio` — 보통 품질의 새 짝 후보(`04-breeding` 2.2)와 같은 규칙 |
| 경험 연수 | `species.runStart.age` (짝 후보와 같은 셈) |
| 에너지 | 지방 상한(`01-formulas` 2.1) × `energy.runStartRatio` |
| 깃털 | `feather.runStart` |
| 짝 · 부상 | 없음. 첫 짝은 `pairing` 첫 단계의 짝 후보 관문에서 |

- **왜 종 평균인가**: 같은 시드면 같은 출발이어야 리더보드가 공정하다(gdd 11.4). 계보를 강하게 만드는 것은 짝 고르기와 새끼 고르기다(gdd 5.4). 출발 개체에 난수를 넣으면 '좋은 시작 다시 뽑기'가 생긴다.
- **왜 성별을 고르게 하나**: 박새는 암수의 일이 다르다 — 암컷은 산란 비용·포란을 지고, 수컷은 둥지 자리 경쟁(`patrol`)과 짝 먹여 주기(`feedMate`)를 한다(`04-breeding` 3장). 같은 종을 두 방식으로 해 볼 수 있는 것이 다시 할 이유가 된다. 계승 뒤의 성별은 고른 새끼의 성별이다.
- S-03 화면: 성별 2개 + 성별마다 한 줄 설명(문구는 콘텐츠), 스탯 6개의 현재 등급 / 잠재력 등급 범위(4장).

| 예시 (박새) | 잠재력 | 현재값 | 화면 (현재 / 잠재력) |
|---|---|---|---|
| 비행 (적성 C) | 46 | 39.1 | E / D~C |
| 채식 (A) | 70 | 59.5 | C / B~A |
| 경계 (A) | 70 | 59.5 | C / B~A |
| 체력 (D) | 34 | 28.9 | F / F~E |
| 과시 (B) | 58 | 49.3 | D / C~B |
| 사회 (A) | 70 | 59.5 | C / B~A |

- 지방 상한 `50 + 0.5 × 28.9` = 64.45 → 에너지 **45.12**. 깃털 **80**. 경험 **1**.

## 3. 새끼 — 성별과 잠재력이 정해지는 때

| 언제 | 무엇 |
|---|---|
| 부화(`incubation` 마지막 단계, `04-breeding` 5장의 `hatchRate` 판정) | 부화한 새끼마다 **성별**(`u < heredity.femaleShare`이면 암컷) → **잠재력 6개**(`01-formulas` 5장, 어미·아비 = 플레이어와 짝의 잠재력). 새끼마다 성별 → 스탯 순서로 난수를 쓴다 |
| `nestling` · `postFledge` 단계마다 | 은수저 충족도(`01-formulas` 6.1, `04-breeding` 6.3의 가감) |
| 독립(계승 화면 직전) | 은수저 지수 확정 → **시작 스탯**(`01-formulas` 6.2, 학습 보너스 포함) · 첫 겨울 보정(6.3) |

- 시작 스탯은 잠재력을 넘지 않는다: `min(잠재력, 6.2의 식)`(`01-formulas` 1.1).
- 스탯 순서는 `species.aptitude`의 키 순서(`flight` `foraging` `vigilance` `stamina` `display` `social`).
- 새끼의 성격(대담·소심)과 선천 특성(체격·깃 선명도·날개·대담성, gdd 5.3)은 **v0에 없다**(9장).

| 예시 — 은수저 0.545, 학습 `varied`(채식 +4) | 잠재력 → 화면 | 시작 스탯 → 화면 |
|---|---|---|
| 비행 | 46 → D~C | `46 × 0.3635` = 16.72 → G |
| 채식 | 76.4 (`01-formulas` 5장 예시) → A~S | `76.4 × 0.3635 + 4` = 31.77 → E |
| 경계 | 72.4 → B~A | 26.32 → F |
| 체력 | 34 → F~E | 12.36 → G |
| 과시 | 58 → C~B | 21.08 → F |
| 사회 | 70 → B~A | 25.45 → F |

(`0.3635 = silverSpoon.startStatBase + startStatPerIndex × 0.545`)

## 4. 잠재력 등급 범위 — S-03 · S-15 · S-20(지난 짝) · S-24

잠재력은 숫자로 보이지 않는다. **연속 2등급**으로 보인다.

```
아래 = 등급(max(stats.min, 잠재력 − heredity.rangeWithin))
위   = 등급(min(stats.max, 잠재력 + heredity.rangeWithin))
표시 = 아래 == 위 ? 아래 : "아래~위"
```

- 진짜 잠재력은 늘 범위 안에 있다(정직한 표시, gdd 3장 원칙 5). 범위 폭이 등급 폭과 같아서 거의 늘 2등급이다 — 예외는 `G`·`S`처럼 넓은 등급의 가운데.
- 플레이어 자신의 잠재력도 같은 규칙으로 보인다. 현재값은 등급 하나(`01-formulas` 1.1).

| 예시 입력 (`rangeWithin` 5) | 출력 |
|---|---|
| 64.4 | `C~B` |
| 65 | `B~A` |
| 75 | `A~S` |
| 100 | `S` |
| 3 | `G` |

## 5. 계승 화면 — 관문 `inheritance` (S-24)

열리는 때와 순서는 `00-core-loop` 6.1 그대로: 1마리 이상 독립 → 총 번식 수 +1 확정 → 이 관문. 단계 흐름의 끝(판정 뒤)에 열린다.

| 선택지 id | 무엇 |
|---|---|
| `inherit.stay` | 이 개체로 1년 더 (잔류). 이어서 2차 번식 관문(`00-core-loop` 6.2) |
| `inherit.chick.<n>` | n번째 새끼로 계승. n = 1부터, 부화 순서 |

- 결정 1회. 새끼가 1마리여도 선택지 2개다(`00-core-loop` B-7). 계승 확인 시트(아트 `docs/ux/screens.md` 3장)는 화면의 일이고 결정으로 세지 않는다.
- 독립하지 못한 새끼는 카드에 없다.

화면 정보

| 어디 | 무엇 |
|---|---|
| 맨 위 | "번식 성공 — 총 N" (`02-scoring` 5장) |
| 지금 개체 | 나이 · 노화 위험 배율(`01-formulas` 3.1) · 짝 유대 · **1년 생존 예상**(6장) |
| 새끼 카드마다 | 성별 · 잠재력 등급 범위 6개 · 은수저 지수(소수 둘째 자리) · **1년 생존 예상**(6장) · 첫 겨울 위험 배율(소수 둘째 자리) |

- 두 쪽 모두 같은 '1년 생존 예상'을 보여 비교하게 한다. 잔류의 힘(경험·높은 스탯)과 대가(노화), 계승의 힘(잠재력)과 대가(첫 겨울·낮은 시작 스탯)가 이 숫자 하나에 모인다.
- 카드에 6개 범위가 다 들어가지 않으면 펼침으로(아트). 정보를 빼지는 않는다.

## 6. 1년 생존 예상

이벤트를 넣지 않은 **기준 위험**으로 앞으로 1년을 곱한다. 난수 없음, `preview`와 같은 원칙(`01-formulas` 7.2).

```
1년 생존 예상 = Π(앞으로 24시기의 단계마다) (1 − 그 단계의 기준 위험)
```

| 입력 | 가정 |
|---|---|
| 단계 | 관문 다음 단계부터 24시기 — **기본 단계표**(`data/calendar/<종>.json` `periods`)대로. 재번식은 넣지 않는다. 박새는 늘 38단계 |
| 기준 위험 | `01-formulas` 3.1의 식. 장소 = **지금 장소**(단계의 계절 위험 등급), 행동 = `forage`, 국면 = 그 단계의 국면, 무리 보정은 국면대로 |
| 1로 두는 것 | `riskMod` · 지방 · 배고픔 · 깃털 · 부상 보정 |
| 경계 · 비행 | 지금 값 그대로(성장·노화 없음). 비행은 3.1의 포식자 회피 보정(#216)으로 들어간다 |
| 나이 · 경험 연수 | `period 1`을 지날 때 +1 — 노화 보정과 첫 겨울 보정(나이 0 · `winter`)이 그에 따라 바뀐다 |
| 새끼 | 나이 0, 경험 0, 경계 · 비행 = 시작 스탯, 첫 겨울 보정 = 그 새끼의 은수저로(`01-formulas` 6.3) |

- 단계마다 `risk.floor`~`risk.cap`으로 자른 뒤 곱한다.
- 표시: 정수 %(0.5 올림). 옆에 "사건 제외" 표시 — 실제는 이벤트·굶주림만큼 더 낮다.
- 새끼의 경계는 실제로는 1년 동안 자란다(성장 배율). 예상은 그만큼 새끼에게 보수적이다 — 일부러 둔다(예상이 계승 쪽으로 과하게 기울지 않게).

| 예시 — 박새, `period 12` 마지막 단계의 관문, 장소 `forest-edge`(사계절 위험 `medium`) | 출력 |
|---|---|
| 잔류: 나이 3, 경계 62, 비행 55, 경험 3 | **82%** (0.8208) |
| 잔류: 나이 1, 경계 59.5, 비행 48, 경험 1 | **86%** (0.8563) |
| 새끼: 잠재력 경계 72.4 · 비행 46, 은수저 0.545 → 경계 26.32 · 비행 16.72(3장), 첫 겨울 ×1.47 | **81%** (0.8051) |
| 새끼: 같은 잠재력, 은수저 1.0 → 경계 36.2 · 비행 23, 첫 겨울 ×1.2 | **82%** (0.8187) |

(잔류 나이 3: `period 13–24` 14단계는 노화 ×1.25, `period 1–12` 24단계는 나이 4 · 노화 ×1.5 · 경험 4.)

(비행을 `risk.flightRef`(40)로 두면 보정 1 — 이 넷은 0.7688 · 0.8184 · 0.7804 · 0.7912(장소 위험 × 0.8(#22) 전 값). 비행 보정(#216) 전 예시였다. 새끼는 비행 시작 스탯이 낮아 회피 보정이 1보다 커진다 — 계승의 대가가 이 숫자에 함께 들어간다.)

## 7. 계승하면 — 넘어가는 것과 처음부터인 것

`00-core-loop` B-4의 표를 이것으로 바꾼다.

| 항목 | 새 조작 개체 |
|---|---|
| 성별 · 잠재력 | 고른 새끼의 것 |
| 나이 · 경험 연수 | 0 · 0 (`period 1`에서 1 · 1) |
| 스탯 | 시작 스탯(3장). 나이 ≤ `silverSpoon.growthUntilAge` 동안 은수저 성장 배율 |
| 에너지 | 새끼의 지방 상한 × `energy.inheritStartRatio` |
| 깃털 | `feather.runStart` (새 깃) |
| 부상 | 없음 |
| 짝 · 유대 | 없음. 이듬해 `pairing`에서 새 후보만(지난 짝 카드 없음) |
| 장소 | 지금 장소 그대로 |
| 시간 | 그대로 이어진다(같은 해, 다음 단계). 그 해의 2차 번식은 없다(`00-core-loop` 6.2) |
| 총 번식 수 | 그대로 — 계보의 점수다 |
| 이번 시기의 `riskMod`·`foodMod` | 그대로 — 개체가 아니라 세계에 걸린 것 |
| 계절 방침 | 그대로 — 플레이어의 방침이다 |
| 도감 · 업적 | 그대로(메타, gdd 5.4) |
| 지역 지식 · 노래 레퍼토리 | v0에 없는 시스템 — 넘길 것이 없다. 생기면 이 표에 더한다 |

- **떠난 부모 · 그 짝 · 고르지 않은 새끼는 시뮬레이션하지 않는다.** 화면에도 다시 나오지 않는다(v0). gdd 4.1의 'NPC로 마주침'은 가족 단위 종(M4)에서 다시 본다.
- 예시: `period 12`에 3장 예시의 새끼(체력 시작 12.36)로 계승 → 지방 상한 `50 + 0.5 × 12.36` = 56.18 → 에너지 **33.71**, 깃털 **80**, 나이 0. 다음 단계는 `period 13`의 첫 `molt`. `period 23–24`의 `winter` 2단계에 첫 겨울 보정, `period 1`에 나이 1.

### 7.1 잔류하면

아무것도 바뀌지 않는다. 같은 단계에서 2차 번식 관문으로(조건이 참일 때, `00-core-loop` 6.2).

## 8. 가계도 — 생애 기록(S-30)

조작했던 개체마다 한 줄. 세대 수는 `02-scoring` 4장 `generations`.

| 칸 | 값 |
|---|---|
| 세대 | 1부터 |
| 성별 | |
| 조작 기간 | 시작(나이·연·시기) ~ 끝 |
| 끝난 이유 | 계승 / 사망(원인, `00-core-loop` 8장) |
| 확정된 번식 수 · 독립시킨 새끼 수 | 그 개체를 조작하는 동안만 |

- 계승으로 떠난 뒤의 번식은 **기록하지 않는다**(시뮬레이션하지 않으므로, 7장). 점수에도 넣지 않는다(gdd 4.1).
- 엔진 로그 `inheritance`(`03-contracts` #33 4절)에 위 칸을 담으면 화면과 QA가 같은 것을 읽는다.
