## 1. 이 문서가 정하는 것

화면마다 **플레이어가 결정하려면 무엇을 봐야 하는가**. 화면의 배치·모양·흐름은 아트의 `docs/ux/screens.md`가 정한다. 둘이 어긋나면 이 문서가 우선이다(01-collaboration 13장).

- 범위: **M3 친구 알파 박새**에 쓰는 화면(v1은 M1). S-14 계절 방침·S-32 리더보드·S-34 칭호는 이 판에서 정보를 정하지 않는다(4장 아래). 화면 ID는 `docs/ux/screens.md` 2장을 따른다.
- 화면은 확률·점수를 계산하지 않는다. 숫자는 모두 엔진이 준다(`preview`·`getView`, `03-contracts` 1.5). 엔진이 아직 주지 않는 값은 4장에 모았다.

## 2. 공통 표시 규칙

| 무엇 | 형식 | 근거 |
|---|---|---|
| 사망 위험 · 둥지 손실 · 새끼 사망 확률 | 0.1% 미만 → "0.1% 미만" / 10% 미만 → 소수 첫째 자리 % / 그 이상 → 정수 %. 색 띠 낮음·보통·높음 | `01-formulas` 7.1 |
| 에너지 변화 | 부호 붙은 정수 하나 | `01-formulas` 7.2 |
| 예상 스탯 상승 | 소수 첫째 자리. 등급이 바뀌면 "C → B" | `01-formulas` 7.3 |
| 판정형 선택지 성공 확률 | 정수 % | `03-events` 5.3 |
| 짝 지시 수락률 | **등급만** — 높음·보통·낮음·불가+이유. 숫자 없음 | `01-formulas` 7.4 |
| 스탯 | 등급 G~S. 상세 화면(S-15)에서만 0~100 | gdd 5장 |
| 숨은 값(짝의 잠재력·성격, 새끼의 잠재력) | 정확한 값을 보여주지 않는다. 등급 **범위**나 정직한 신호로 | gdd 5.4 · 7.2 |

- **보여준 확률은 실제 판정 확률과 같다.** 화면에서 반올림만 한다.
- 글(`text`)에는 숫자를 쓰지 않는다. 숫자는 화면이 엔진 값으로 붙인다(`03-events` 5.3).

### S-10 카드 턴 — 패에서 고르기 (v2, `12-card-turn`)

카드 턴이 들어가면 위 표의 "행동마다" 줄은 **카드마다**가 된다. 나머지(시기·에너지·굶주림 경고·장소·환경 카드)는 그대로다.

| 정보 | 왜 · 근거 |
|---|---|
| **패** — 이번 단계에 뽑힌 카드와 장수(같은 카드는 "×2"로 묶음, `ViewModel.routine.hand`) | 고를 거리가 운으로 정해진다(12장 2.1·2.2) |
| **늘 있는 카드 3장** — 옮기기 · 채식(기본) · 쉬기. 패와 구분되게, 장수에 세지 않음 | 운이 판을 끝내지 않는다(2.3). "나머지 쉬기" = 남은 칸만큼 쉬기(2.4) |
| 카드마다 **에너지 변화 · 위험%(습격이 들어가면 습격%) · 예상 성장** | S-10과 같은 자. 판정 순서가 에너지 → 위험(#52) |
| **칸 줄** — 칸 수만큼 자리, 고른 순서대로. 칸 아래에 이어 계산한 예상 에너지 | 순서가 결과를 바꾼다(3장). 빈 칸은 쉬기로 실행된다고 보인다 |
| **예산 막대** — "에너지 18 중 14"(행동 비용 합 / `stepBudget × n`). 쉬기·옮기기는 막대를 움직이지 않음 | 한도가 고르는 순간에 보이게(3장) |
| 고를 수 없는 카드는 흐리게 + **이유**("에너지 부족" · "패에 없음") | 엔진 `disabled.reason` 그대로 |
| 배고픔 구간(`risk.hungerFrom`) 아래로 내려가는 칸은 노란 경고 | 굶주림-포식 트레이드오프(gdd 6.1) |

엔진이 v1 다음 조각을 넣으면 더한다(넣기 전에는 그리지 않는다 — 없는 숫자를 보이지 않게):

| 정보 | 근거 |
|---|---|
| 카드마다 **갈래 확률** 대성공·성공·아쉬움(정수 %). 기본 채식·쉬기·옮기기는 갈래 없음 | 12장 4장 |
| **스티커**(호재·악재)와 그 효과 한 줄 — 고르기 전에 | 12장 6장 |
| **남겨 두기** 1장 표시(다음 패에 더해짐, 기회 카드는 계절·장소가 바뀌면 사라진다고) | 12장 2.5 |
| 겹치기 보너스("2장째 ×1.2")·순서 조합("채식 뒤 훈련: 아쉬움 → 성공") — 칸 줄에서 걸린 칸에 표시 | 12장 3장 |
| 습격 뒤 **대응 확률**(도망·부상·죽음)은 S-15에 늘 | 12장 5장 |

### S-12 판정 결과 (S-10 위에 겹침)

- 예상 대비 실제: 에너지 변화, 스탯 상승. 위험 판정은 "살아남음"만(확률을 다시 보여줄 필요는 없다).
- 짝 지시를 했으면 수락/거절과 그 결과(`00-core-loop` B-6).

### S-13 이벤트 카드

- 제목·본문, 선택지마다:
  - 고정 효과: 효과마다 실제 숫자("에너지 −12", "사망 위험 3%", "둥지를 잃을 위험 30%")
  - 판정형: "경계 판정 90% — 성공: … / 실패: …"
- `fledgeEarly`가 든 선택지: "새끼들이 지금 둥지를 떠난다" + 함께 붙은 `chickLoss`의 마리 수(올림, `03-events` 6.1).

### S-15 개체 상세

- 스탯 6개: 현재값 / 잠재력의 **등급 범위**, 적성 등급
- 나이, 노화 시작 나이(`species.agingStartAge`)와 지금의 노화 위험 배율
- 부상(남은 단계), 이번 시기에 걸린 `riskMod`·`foodMod`

### S-20 짝 후보 (관문 — `pairing` 첫 단계)

- 후보마다: 신호 4개 — 깃 선명도(등급) · 노래(등급) · 나이(1년생/성조) · 성격 힌트(글) — 와 **나를 받아들일지(예 / 아니오)**. 아니오인 카드는 고를 수 없고 이유("노래가 더 필요하다")를 보인다. `04-breeding` 2.3 · 2.4
- 지난 짝이 있으면 맨 앞 카드: 스탯 등급 범위, 성격(확인), 유대. 재결합하면 유대가 오른다(`04-breeding` 2.2).

### S-21 짝 지시 · S-22 육아 방침 · S-23 둥지 진행 (번식 단계)

| 화면 | 정보 |
|---|---|
| S-21 짝 지시 | 둥지 국면 첫 단계에만. [지시 없음] + 지시마다 수락률 **등급**(숫자 없음), 불가면 이유 + 도움. 짝 유대·성격(힌트/확인). 거절되면 "짝이 ~ 대신 ~ 했어요 (효과 −N%)" (`04-breeding` 3장) |
| S-22 육아 방침 | 7항목(`04-breeding` 6.1)과 방침 조합의 **이소 기대 수**(소수 첫째 자리)·**내 번식 비용**(단계당 에너지, 정수) — 항목을 바꿀 때마다 다시 계산(6.4). 설정은 `nestling` 첫 단계, 조정은 `postFledge` 첫 단계에 한 번(6.2) |
| S-23 둥지 진행 | 국면 스텝퍼 **6칸**: 짝 → 둥지 → 산란 → 포란 → 육추 → 이소·돌봄, 끝 표시 **독립**. 단계마다 둥지 손실 위험%, 살아 있는 알·새끼 수 |

- 스텝퍼는 국면(`00-core-loop` 2.2)과 1:1이다. '이소'는 국면이 아니라 육추가 끝나는 순간이다. 재번식(`00-core-loop` 4.4)은 `nestSite`부터 다시 시작하고 '짝' 칸은 완료로 둔다.
- 짝이 죽어 단독 육아가 되면 S-23에 **둥지 포기** 선택지(`00-core-loop` B-2).

### S-24 독립 · 계승 결정 (관문 — `postFledge` 마지막 단계)

- **먼저 "총 번식 수 +1 확정"을 보여 준다.** 계승을 고르든 잔류하든 이미 확정이다(`00-core-loop` 6.1).
- 새끼 카드마다: 성별, 잠재력 **등급 범위** 6개(예 "C~B"), 은수저 지수, **1년 생존 예상**, 첫 겨울 위험 보정(`01-formulas` 6.3)
- 현재 개체: 나이, 노화 위험 배율, 짝 유대, **1년 생존 예상** — 두 쪽이 같은 숫자로 비교된다(`05-inheritance` 5 · 6장)
- 잔류를 고르면 이어서 **2차 번식 여부**(`00-core-loop` 4.4의 조건이 참일 때만): 에너지 비용(`species.secondBrood.energyCost`), "털갈이 4단계가 번식으로 바뀐다 → 겨울 깃털 부족" 안내
- 계승은 되돌릴 수 없다 — 확인을 한 번 더(아트 `screens.md` 3장)
- 잠재력 범위는 연속 2등급(`05-inheritance` 4장), 넘어가는 것·처음부터인 것은 같은 문서 7장. 확인 시트의 비교표는 그 표에서 고른다
- 선택지 `inherit.stay` / `inherit.chick.<n>` — 결정 1회(확인 시트는 세지 않는다)

### S-11 지도 (v2 — M3 정보용)

- 장소마다: 먹이·경쟁 등급, 위험%(지금 개체 기준, S-10 옮기기 펼침과 **같은 숫자**), 지금 장소의 연속 체류(고갈) 표시, 이동 에너지 비용.
- 위험% 숫자와 이동 비용은 **지금 옮길 수 있는 곳**(옮기기 목적지, 최대 4개)에만 — 엔진 `preview`가 그곳에만 있다. 나머지 장소는 등급만, 숫자 자리는 비운다("옮길 수 있을 때"). 모든 장소 숫자는 필요해지면 4장에 엔진 값으로 더한다.
- **옮기기 입력은 여기서 받지 않는다** — 결정은 S-10 옮기기 펼침 하나(#38). 지도는 "어디가 어떤 곳인지" 보는 화면이다. 지도에서 장소를 누르면 S-10 옮기기 펼침의 그 카드로 간다(배치는 아트).
- 장소 설명 글·그림은 도감(S-33) 장소 항목과 같다.
- 지역 지식(gdd 5.1, 장소 정보 공개도)은 아직 엔진 규칙이 없다 — **M3에서는 공개도로 숨기지 않는다**(위 목적지 범위만). 공개도는 규칙이 생길 때(M4 가족 이동과 함께).

### S-31 가계도 · 가문 기록 (v2 — M3)

- 세대마다 한 칸: 세대 번호, 성별, 산 해, 그 개체의 번식 수(독립시킨 해 수), 끝난 이유(계승 / 사망 원인 글 — `00-core-loop` 8장), 계승한 새끼로 이어진 선.
- 맨 위에 그 런의 **총 번식 수**(점수)와 세대 수 — S-30과 같은 숫자.
- 계승하지 않은 새끼는 그리지 않는다(떠난 개체는 시뮬레이션하지 않음 — `05-inheritance` 9장과 같은 원칙). 잠재력·스탯은 보이지 않는다(기록이지 결정 화면이 아님).
- 지난 런의 가계도는 M3에서 마지막 1판만(저장 범위는 클라이언트 판단, 리더보드와 무관).

### S-33 도감 (v2 — M3)

- 갈래: 포식자 · 먹이·현상 · 장소 · 이벤트(`data/codex/`, 콘텐츠). 처음 보는 항목은 '?', **겪으면 등록**(gdd 10장 포식자 상성 줄).
- 항목마다: 이름·그림·설명 글(콘텐츠), 처음 만난 런·세대, 만난 횟수. 포식자는 상성(무엇이 통하는지 — 예 새매 → 덤불)을 등록 뒤에 보인다.
- **확률은 도감 등록과 무관하게 늘 정확히 보인다**(원칙 5 — "보여준 확률은 실제 판정 확률과 같다", 2장). 도감은 수치 보너스·정보 해금이 아니라 **기록과 설명**이다(gdd 5.4 "정보 해금 위주"는 설명·상성 글을 여는 것으로 읽는다). → 아트 `docs/ux/screens.md` 2장 S-33의 "알아낸 확률이 S-10·S-13에 더 정확히 뜬다"는 이 문서와 어긋난다 — 이 문서가 우선(1장), 아트에 고쳐 달라고 요청.
- 도감은 런이 끝나도 남는다(gdd 5.4). 저장 위치는 클라이언트.

### S-30 게임 오버 · 생애 기록

- 최종 점수 = 총 번식 수(정산 없음), 사망 원인(`00-core-loop` 8장 코드를 글로), 부가 기록(`02-scoring` 4장).

### S-01 · S-02 · S-03 · S-40
