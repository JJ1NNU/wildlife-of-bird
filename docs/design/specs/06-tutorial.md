## 1. 방침 — 따로 된 튜토리얼 판은 없다

첫 판이 곧 튜토리얼이다. **어떤 상황을 처음 만나는 순간** 그 화면에 짧은 도움말(팁) 1장을 띄운다.

- 왜: 친구 알파 용도의 1인 취미 게임이다(gdd 1.3). 대본형 튜토리얼 판은 만들 것(전용 시드·화면·분기)이 많고, 끝나면 버려진다. 팁은 진짜 판 위에서 진짜 숫자로 가르친다.
- **규칙은 바꾸지 않는다.** 첫 판도 보통 판과 같은 엔진·같은 난수다. 쉬운 첫 판(보호 장치)은 넣지 않는다 — 점수·리더보드·QA 측정이 갈라진다(원칙 8). 필요하면 알파 피드백 뒤에 따로 정한다(6장).
- 팁은 **결정이 아니다**: `act`를 부르지 않고, 결정 예산(`00-core-loop` 5장)에 세지 않고, `RunState`·리플레이에 들어가지 않는다. 엔진 변경 없음 — 조건은 모두 지금 `ViewModel`(`getView`)과 `preview`로 판단한다.

## 2. 팁의 모양

| 항목 | 규칙 |
|---|---|
| 한 번에 | **1장만**. 같은 순간 둘 이상이면 3장 표의 번호 순으로 줄 세워 하나씩 |
| 크기 | 제목 1줄 + 본문 2줄 이하. 가리키는 자리(화살표·테두리)가 있다 — 배치는 아트 |
| 닫기 | 탭 한 번. 닫기 전에도 뒤 화면을 누를 수 있다(막지 않는다) — 단 S-24 계승 확인은 팁을 먼저 닫아야 한다(되돌릴 수 없는 선택, 4장 T-30) |
| 다시 안 뜸 | 팁마다 한 번 본 뒤에는 그 기기에서 다시 뜨지 않는다. 런이 바뀌어도(계승·새 판) 그대로 |
| 끄기 · 다시 보기 | S-40 설정에 "도움말 켜기/끄기"와 "도움말 처음부터 다시". 기본은 켜짐 |
| 저장 | 클라이언트 기기 저장(본 팁 id 목록). 게임 저장과 따로 — 저장 버전 정책(엔진 #534)과 무관 |
| 숫자 | 문구(`text`)에 숫자를 쓰지 않는다(`screens.md` 2장). 숫자가 필요하면 화면이 가리키는 자리의 엔진 값을 그대로 가리킨다 |

문구 키: `tutorial.<팁 id>.title` · `tutorial.<팁 id>.body` (콘텐츠 #537, 파일 위치는 콘텐츠가 `data/text/`에서 정한다).

## 3. 런 시작 전 — 온보딩 3줄

S-02(종 선택)에서 박새를 고른 뒤, **첫 판에만** S-03 위에 한 장(T-00). 게임의 목표를 세 줄로:

1. 점수는 **번식에 성공한 횟수**다(새끼 수가 아니다, gdd 11.1).
2. 지금 이 새가 죽으면 판이 끝난다.
3. 새끼가 독립하면 **그 새끼로 갈아탈 수 있다** — 그렇게 세대를 잇는다(gdd 4.1).

## 4. 팁 목록과 순서 — 확률을 읽는 순서대로

순서의 뼈대는 "숫자 하나 → 확률 하나 → 확률 여럿 → 숨은 값"이다(`screens.md` 5장). 박새 첫 판에서 상황이 오는 순서와 거의 같다. **번호 = 줄 세우기 우선순위**.

| id | 언제 (처음 참일 때) | 화면 · 가리키는 곳 | 가르치는 것 |
|---|---|---|---|
| T-00 | 첫 판 S-03 진입 | S-03 | 3장의 목표 3줄 |
| T-01 | S-10 첫 진입 (`routine` 있음) | S-10 패 | 패에서 칸 수만큼 골라 **순서대로** 실행한다. 칸 수·나오는 장수는 스탯·경험이 정한다(`12-card-turn` 2.2) |
| T-02 | T-01을 닫은 직후 | 카드의 에너지 변화 | 카드마다 **에너지 변화**가 먼저 보인다. 에너지 0이면 바로 죽는다(`00-core-loop` B-1) |
| T-03 | T-02를 닫은 직후 | 카드의 위험% | **위험%** = 그 칸에서 일어날 확률 그대로다. 보여준 숫자로 판정한다(`screens.md` 2장) |
| T-04 | 처음으로 카드가 한도에 막힘(고를 수 없음 · 이유 에너지 부족) | 에너지 막대 | 한 단계에 쓸 수 있는 몫이 있다. 채식을 먼저 넣거나 칸을 비워 쉰다(`12-card-turn` 3장) |
| T-05 | 처음으로 `옮기기`를 펼침 | 목적지 카드 | 장소마다 먹이·위험이 다르고, 오래 머물면 먹이가 준다(`00-core-loop` 3.2) |
| T-06 | 처음으로 `starving` 참 | 굶주림 경고 | 배가 고프면 위험이 오른다 — 굶주림과 포식은 맞바꾸는 관계다(gdd 6.1) |
| T-07 | 첫 S-12 판정 결과 | 예상 대비 실제 | 예상과 실제가 다를 수 있다 — 판정 결과에서 확인한다 |
| T-08 | 첫 이벤트 관문(`gate.kind = 'event'`) | 선택지의 효과·판정 % | 선택지마다 대가가 다르다. 판정형은 성공 %가 붙는다(`03-events` 5.3) |
| T-10 | 첫 짝 후보 관문(`mateCandidate`) | 후보 카드의 신호 · 받아들일지 | 후보의 속은 **신호**로만 보인다(정확한 값 없음). 받아들이지 않을 후보는 이유가 보인다(`04-breeding` 2장) |
| T-11 | 첫 짝 지시(`mateOrder`) | 수락률 등급 | 짝은 거절할 수 있다. 수락률은 **등급**(높음·보통·낮음)으로만 보인다(`01-formulas` 7.4) |
| T-12 | 첫 둥지 자리(`nestSite`) | 구멍마다 둥지 손실 % | 둥지가 털리는 확률이 자리마다 다르다 |
| T-13 | 첫 산란수(`clutchSize`) | 이소 기대 수 · 은수저 | 많이 낳으면 한 마리 몫이 준다 — 기대 수는 소수로 보인다 |
| T-14 | 첫 육아 방침(`parentingPolicy`) | 이소 기대 수 · 내 비용 | 새끼에게 쓰는 만큼 내 에너지가 든다. 항목을 바꾸면 숫자가 바로 다시 계산된다 |
| T-15 | 처음으로 둥지 손실·새끼 전멸(`recentLog`) | 둥지 진행 | 번식 실패는 판의 끝이 아니다 — 계승만 못 할 뿐 이 새로 계속한다(원칙 7, `00-core-loop` B-5) |
| T-30 | 첫 계승 관문(`inheritance`) | 총 번식 수 +1 · 1년 생존 예상 | 번식은 **이미 확정**이다. 지금 새와 새끼를 **1년 생존 예상**으로 비교해 고른다. 새끼의 잠재력은 등급 **범위**로만 보인다. 계승은 되돌릴 수 없다 |
| T-31 | 첫 2차 번식 관문(`secondBrood`) | 에너지 비용 · 깃털 안내 | 한 해에 한 번 더 낳을 수 있지만 겨울 깃털이 모자라진다 |
| T-40 | 첫 게임 오버 S-30 | 사망 원인 | 무엇이 끝냈는지 보고 다음 판에 쓴다. 세대를 이은 기록이 남는다 |

- **첫 단계의 팁은 T-01·T-02·T-03 셋까지**(한 화면에 줄 세워 하나씩). 그 밖의 팁은 상황이 처음 올 때 하나씩 — 한 단계에 팁이 셋을 넘으면 넘친 것은 다음 단계로 미룬다(번식기 관문이 몰리는 단계 대비). 단 T-30은 미루지 않는다.
- 카드 턴의 나머지 조각이 들어오면 팁을 더한다(그 기능이 엔진에 들어온 PR에서 이 표를 고친다):

| id | 언제 | 가르치는 것 | 들어오는 때 |
|---|---|---|---|
| T-20 | 패에 결과 갈래가 처음 보임 | 대성공·성공·아쉬움 **세 확률**을 미리 본다. 관련 스탯이 높을수록 대성공 쪽으로 옮겨진다(`12-card-turn` 4장) | 갈래 구현 |
| T-21 | 처음 습격(도망·부상) | 위험%는 **습격** 확률이고, 습격에서 도망·부상·죽음이 갈린다. 부상 뒤에는 쉬어서 대응한다(`12-card-turn` 5장) | 습격 구현 |
| T-22 | 패에 스티커 카드가 처음 보임 | 호재·악재는 고르기 전에 보인다 | 스티커 구현 |
| T-23 | 처음으로 남겨 두기가 가능 | 한 장을 다음 단계로 아껴 둘 수 있다 | 남겨 두기 구현 |

### 예시 (입력 → 출력, QA e2e용)

1. 새 기기, 첫 판: S-02 박새 → S-03 → **T-00** → 시작 → S-10 → **T-01** 닫기 → **T-02** 닫기 → **T-03** 닫기 → 팁 없이 카드 고르기.
2. 같은 기기 두 번째 판: S-03 → (T-00 없음) → S-10 → 팁 없음.
3. 첫 단계에 굶주림 경고가 이미 켜져 있음: T-01 → T-02 → T-03, **T-06은 다음 단계**로(첫 단계 셋 제한).
4. 첫 계승 관문이 뜬 단계에 이미 팁 셋을 봤음: **T-30은 그래도 뜬다**, 닫아야 계승 확인으로 넘어간다.
5. 팁을 띄우고 닫아도 `serialize(state)`가 같다(팁은 상태가 아니다).
6. S-40 "도움말 처음부터 다시" → 다음 S-10 진입에 T-01부터 다시.
