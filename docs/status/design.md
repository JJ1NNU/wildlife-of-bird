## 메모 (다음 근무의 나에게)
- 명세 예시 숫자는 **데이터 파일 값으로 스크립트 계산**해서 넣는다. 데이터를 바꾸면 예시를 다시 계산할 것 — 엔진·QA가 테스트로 쓴다
- 효과 등급 이름은 스키마의 `Tier`·`RiskTier`만. 새 열거를 만들지 말 것. `riskMod`는 올리기만 한다(줄이는 등급 없음) — 이벤트에서 '안전'은 다른 선택지의 대가로 표현
- 판정 순서(에너지 → 스탯 → 위험)와 "점수 확정 → 계승 화면" 순서는 여러 문서가 기댄다. 바꾸면 전부 고칠 것
- v0 수치는 목표에서 거꾸로 잡은 것. QA 리포트 전에는 감으로 바꾸지 않는다
- 박새 결정 예산 62~72회, 번식 완전 포기 해 약 50(34단계). 가장 흔한 해 62가 하한에 가깝다 — QA M-11 측정을 기다린다
- 단계표는 **국면만** 담는다. 관문은 국면 경계(4.6), 행동 목록은 v0에서 전 국면 6개
- 1년 최대 2번식은 '그 해 둥지 2개 미만' 관문 조건이 보장한다(02-scoring 3장)
- 머지는 `gh pr merge <번호> --repo JJ1NNU/wildlife-of-bird --squash --delete-branch` **단독 한 줄** — 동작 확인(라운드 4)
- Windows 작업 폴더는 `core.autocrlf=true` — `npm run format` 뒤 `version.json`이 바뀐 것처럼 보이면 커밋하지 말 것. Node 스크립트 경로는 저장소 안 상대 경로로
- `data/balance/breeding.json`은 검증기가 읽지 않는다(#121 전까지). 키를 바꾸면 04 예시를 다시 계산할 것
- 관문 시점: 짝 지시·육아 방침 = 판정 1 **전**, 나머지 관문 = 흐름 **끝**(효과는 다음 단계부터). 산란수 관문 뒤 둥지 단계는 8(`laying` 2 + 3 + 3)
- 이 worktree는 main을 체크아웃할 수 없다(다른 worktree가 씀) — 상태 파일은 `git checkout --detach origin/main` → 커밋 → `git push origin HEAD:main`
