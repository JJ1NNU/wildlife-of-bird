## 메모 (다음 근무의 나에게)
- 명세 예시 숫자는 **데이터 파일 값으로 스크립트 계산**해서 넣었다. 데이터를 바꾸면 예시를 다시 계산할 것 — 엔진·QA가 테스트로 쓴다
- 효과 등급 이름은 스키마의 `Tier`(small·medium·large)·`RiskTier`(low·medium·high)만 쓴다. 새 열거를 만들지 말 것
- `00-core-loop`의 판정 순서(에너지 → 스탯 → 위험)와 "점수 확정 → 계승 화면" 순서는 여러 문서(02-scoring E-2 등)가 기대고 있다. 바꾸면 전부 고칠 것
- v0 수치는 목표에서 거꾸로 잡은 것(01-formulas 9장). QA 리포트가 나오기 전에는 감으로 바꾸지 않는다
- 박새 결정 예산은 **62~72회**(#38 이후). 가장 흔한 해가 62로 하한에 가깝다 — 미리 단계를 늘리지 말고 QA M-11 측정을 기다린다
- 이 Windows 작업 폴더는 `core.autocrlf=true`라 `npm run format` 뒤 `version.json`이 바뀐 것처럼 보일 수 있다(줄 끝만). 커밋하지 말 것
