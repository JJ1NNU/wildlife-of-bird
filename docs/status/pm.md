## 메모 (다음 근무의 나에게)
- **근무 종류 판정**: 대시보드의 "마지막 PM 근무 종류"가 '라운드 끝'이므로 다음은 **라운드 시작**이다(pm.md 7장).
- `gh`는 이제 PATH에 있다(대표가 추가, 앱 재시작 후). 머지는 자동 승인 모드 판정에 따라 될 때도, 막힐 때도 있다 — 막히면 대표에게.
- PowerShell은 `gh --jq` 따옴표를 망가뜨린다. jq를 쓸 때는 Bash로.
- 부서별 작업 폴더: `C:\dev\wb-<부서>` (PM은 `C:\dev\wild-bird-studio`).
- 아직 만들지 않은 것: `docs/studio/retros.md` — M0 관문 통과 후 첫 회고 때 만든다(02-roadmap 5장 4번). 미리 만들지 않는다.
- M1 이슈 #21~#26은 라운드 2 끝에 **확정**했다. 우선순위(P0/P1)는 M0 관문 통과 때 다시 매긴다.
- 머지: `gh pr merge`를 다른 명령과 `&&`로 길게 묶으면 막히는 경우가 있었다. 머지는 한 번에 하나씩.
- 대표에게 같은 질문을 두 번 하지 않는다. 대표가 #1에 답하면 `decisions.md`에 D-0xx로 기록하고 해당 `needs:ceo` 이슈를 닫는다.
- **머지 전 확인 두 가지 (라운드 1의 실수에서)**
  - PR의 CI가 **최신 main 기준**인지 본다. 다른 PR이 그 사이 들어갔으면 CI를 다시 돌린 뒤 머지한다(#39 + #41이 각자 통과했는데 합쳐서 main을 깨뜨렸다)
  - **쌓인 PR**(base가 다른 PR의 브랜치)이 있으면, 아래 PR을 머지할 때 `--delete-branch`를 쓰지 않는다. 브랜치가 지워지면 GitHub가 위 PR을 닫는다(#42). 위 PR의 base를 main으로 바꾼 뒤 브랜치를 지운다
