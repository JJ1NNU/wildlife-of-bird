# 글 스타일 가이드

> 관리: 생태·콘텐츠. 게임 안에서 플레이어가 읽는 모든 글(이벤트·도감·장소·UI·튜토리얼)에 적용한다.
> 출처 대장은 `sources.md`. 미해결 생태 의문은 `fact-check.md`.

## 1. 한 줄 원칙

**본 것을 적는다.** 새가 무엇을 느꼈는지 쓰지 않고, 무엇이 일어났는지 쓴다. 판단은 플레이어가 한다.

## 2. 문체 원칙

1. **담백하게.** 수식어를 줄인다. 감탄·과장·설교를 쓰지 않는다.
2. **의인화 금지.** 새는 사람의 말로 생각하거나 말하지 않는다. 대사·속마음을 주지 않는다.
3. **감정은 상황으로.** "불안했다"가 아니라 불안해 보이는 행동을 적는다.
4. **포식자는 생태계의 일원.** 뱀·담비·까마귀는 새끼를 먹여야 하는 동물이다. 악당·괴물로 묘사하지 않고, 이름에 적대적 수식을 붙이지 않는다.
5. **길이**: 이벤트 본문 2~4문장, 결과 1~2문장, 선택지 한 줄(한국어 30자 이내 권장). 도감 본문은 4~8문장.
6. **현재 시제**를 기본으로 한다. 지금 눈앞에서 일어나는 일로 적는다. 결과 글은 과거 시제를 쓸 수 있다.
7. **2인칭·1인칭을 쓰지 않는다.** "당신의 새끼"가 아니라 "새끼". 플레이어를 호명하지 않는다. 예외: UI 안내 문구.
8. **숫자를 본문에 쓰지 않는다.** 효과는 등급으로 데이터에 적고, 수치 표시는 클라이언트가 한다(4장).

## 3. 좋은 예 · 나쁜 예

### 3.1 의인화

| | 문장 |
|---|---|
| ✗ | 박새는 "이번엔 꼭 지켜내야 해!"라고 다짐하며 둥지를 지켰다. |
| ✓ | 박새가 둥지 구멍 앞 가지에 내려앉아 입구를 향한 채 움직이지 않는다. |

| | 문장 |
|---|---|
| ✗ | 짝이 서운한 마음에 먹이를 덜 가져왔다. |
| ✓ | 짝이 돌아오는 간격이 아침보다 길어졌다. 부리에 든 애벌레도 작다. |

| | 문장 |
|---|---|
| ✗ | 새끼들이 엄마를 그리워하며 울었다. |
| ✓ | 둥지 안에서 새끼들이 입을 벌리고 목을 뻗는다. |

### 3.2 포식자

| | 문장 |
|---|---|
| ✗ | 사악한 누룩뱀이 둥지를 노리고 기어오른다. 악마 같은 포식자다. |
| ✓ | 누룩뱀이 나무껍질을 긁으며 올라온다. 혀를 내밀어 공기를 더듬는다. |

| | 문장 |
|---|---|
| ✗ | 까마귀 떼가 둥지를 습격해 새끼를 학살했다. |
| ✓ | 큰부리까마귀가 입구로 부리를 밀어 넣었다. 새끼 하나가 사라졌다. |

> 도감에서는 한 줄을 더 쓸 수 있다: 그 포식자도 지금 새끼를 키우는 시기라는 사실.

### 3.3 추측을 사실처럼 쓰기

| | 문장 |
|---|---|
| ✗ | 박새는 애벌레가 가장 많아질 날을 미리 알고 그날에 맞춰 알을 낳는다. |
| ✓ | 산란 시기는 해마다 다르다. 봄이 따뜻한 해에는 더 일찍 시작한다. |
| | 근거: SRC-005. "미리 안다"는 출처에 없다 — 기온과 산란 시작일의 관계만 있다. |

| | 문장 |
|---|---|
| ✗ | 박새의 가장 무서운 적은 족제비다. |
| ✓ | 둥지를 노리는 것은 구멍에 들어올 수 있는 동물과, 입구 밖에서 부리를 밀어 넣는 동물이다. |
| | 근거: SRC-001·023. 족제비는 출처가 없다(`fact-check.md` N-4). |

### 3.4 감정의 직접 서술과 과장

| | 문장 |
|---|---|
| ✗ | 절망적인 상황! 이대로라면 모든 것이 끝이다. |
| ✓ | 둥지 안이 조용하다. 입을 벌리는 새끼가 둘로 줄었다. |

### 3.5 숫자 노출

| | 문장 |
|---|---|
| ✗ | 이 선택은 체력을 12 소모하고 사망 위험을 3% 올린다. |
| ✓ | 하루를 더 둥지에 붙어 있는다. (효과는 데이터의 등급으로: `energy: medium`, `deathRisk: low`) |

### 3.6 루틴 칸 결과 — 며칠의 습관 (#190 #200)

루틴의 칸 하나는 약 2일이다(`00-core-loop` 3.5). 칸 결과 글은 **한 순간이 아니라 며칠 동안 되풀이한 습관**으로 쓴다. 한 번뿐인 사건(포식자 습격, 눈에 띄는 한 장면)은 칸 결과가 아니라 **이벤트 카드**에 둔다.

| | 문장 |
|---|---|
| ✗ | 오늘 아침, 참나무 가지에서 애벌레 한 마리를 잡았다. |
| ✓ | 이틀 동안 참나무 가지 끝을 훑으며 애벌레를 찾았다. |
| ✗ | 새매가 덮쳐 왔지만 덤불로 몸을 피했다. (→ 이벤트로) |
| ✓ | 며칠 새 무리의 움직임에 발을 맞추게 되었다. |

- **옮기기 칸** = 옮겨 가서 자리를 익히는 것(이동 + 탐색)으로 쓴다. 박새는 텃새이고 행동권이 작아 이웃 장소로 옮기는 데 하루도 걸리지 않는다.
- 피할 것: '오늘'·'방금' 같은 하루·한순간 말, 시각(아침·저녁) 하나만 박은 장면.

## 4. 용어와 표기

- **국명**: 국가생물종목록 기준의 국명을 쓴다. 박새, 꼬마물떼새, 저어새, 두루미, 쇠박새, 진박새, 동고비, 오목눈이, 큰부리까마귀, 어치, 누룩뱀.
- **학명**: 게임 화면에는 도감의 머리글에만 쓴다. 본문에는 쓰지 않는다. 문서에서는 *Parus minor*처럼 적는다.
- **단계 용어**: 짝 맺기 / 둥지 / 산란 / 포란 / 육추 / 이소 / 이소 후 돌봄 / 독립 / 털갈이 / 이동 / 월동. 기획서 4.3·8장과 같은 말을 쓴다. "부화"는 알이 깨는 순간만 가리킨다.
- **새끼**: 둥지 안은 "새끼", 둥지를 떠난 뒤는 "이소한 새끼", 날 수 있고 부모를 따라다니면 "어린 새". "아기새"는 쓰지 않는다.
- **짝**: "배우자"·"남편"·"아내"를 쓰지 않는다. "짝"으로 통일한다.
- **시기**: 게임 안 글에는 "4월 상반"처럼 쓴다(1년 24시기, 상반/하반 — 기획서 4.2). 데이터의 `period`는 1~24 숫자.
- **숫자**: 본문에서는 한 자리는 한글("둘", "셋"), 두 자리 이상은 아라비아 숫자. 날수·일령은 숫자("17일령").
- **범위**: 물결표를 붙여 쓴다("7~10개", "24~28일").
- **단위**: 일·년·개·마리. 띄어 쓴다("알 7개", "26일").

## 5. 생태 사실에 출처를 붙이는 법

모든 생태 사실 값에는 `sources` 배열로 `sources.md`의 ID를 붙인다.

```json
{
  "incubationDays": { "min": 12, "max": 13, "sources": ["SRC-004"], "factCheck": "needs-review" }
}
```

- 사실 하나에 출처 하나 이상. 출처가 여럿이면 모두 적는다.
- 이벤트·환경 변화에는 `ecologyBasis`(생태 근거 한 줄)와 `sources`를 함께 적는다. `ecologyBasis`는 **그 출처로 주장할 수 있는 범위**를 넘지 않는다.
- **출처의 문장을 그대로 옮기지 않는다.** 사실만 가져와 우리 말로 다시 쓴다. 번역해 옮기는 것도 그대로 옮기는 것이다. 수치·날짜·종명은 그대로 쓰되, 문장 구조와 표현은 새로 짠다.
- 출처에 없는 범위로 넓히지 않는다. 대상 종·지역·연도가 다르면 그 차이를 `ecologyBasis`에 드러낸다(예: 유럽 박새 연구 → "박새류"로 적는다, `sources.md` N-1).
- 게임을 위한 의도적 생태 타협은 기획서에 명시된 것만 허용한다. 글에서 사실처럼 쓰지 않는다.

## 6. `needs-review` 규칙

`factCheck` 값은 `verified` 또는 `needs-review` 둘뿐이다.

`needs-review`를 붙이는 경우:
1. 출처가 없다.
2. 등급 D·E 출처만 있다(`sources.md` 1장).
3. 출처가 있으나 대상 종·지역이 우리 종과 달라 외삽이다.
4. 출처끼리 값이 다르고 어느 쪽이 맞는지 모른다.

`needs-review`를 붙였으면 **반드시** `fact-check.md`의 표에 한 줄 올린다(항목 / 현재 값 / 찾아볼 곳 / 상태). 혼자 해결할 수 없으면 대표에게 올리는 전문가 검수 요청에 묶는다.

출시 기준은 `needs-review` 0이다. 출시 빌드에 남으면 그 데이터는 제외된다(`03-contracts.md` 4.3).

추측으로 빈칸을 채우지 않는다. 모르는 값은 **필드를 쓰지 않는 것**이 `needs-review`보다 낫다. 이번 마일스톤에 쓰이지 않는 값은 아예 만들지 않는다.

## 7. 반복을 피하는 법

같은 풀 안의 이벤트가 비슷하게 읽히면 안 된다.

- 한 이벤트 = 한 상황. 둘을 합치지 않는다.
- 변형은 **조건**으로 둔다: 계절·시기, 장소, 나이, 짝 상태, 새끼 수, 날씨.
- 같은 소재(예: 둥지 포식)를 여러 개 쓸 때는 포식자·시기·대응이 서로 다르게 한다.
- 첫 문장을 같은 형태로 시작하지 않는다(모두 "~가 나타났다"로 시작하면 안 된다).

## 8. 내보내기 전 체크리스트

- [ ] 새가 사람 말로 말하거나 생각하지 않는다.
- [ ] 포식자에게 적대적 수식어가 없다.
- [ ] 모든 생태 사실에 `sources`가 있다. 없으면 `needs-review` + `fact-check.md`에 올렸다.
- [ ] 출처의 문장을 그대로 옮기지 않았다.
- [ ] 출처가 주장하지 않는 것을 쓰지 않았다.
- [ ] 효과가 숫자가 아니라 등급이다.
- [ ] 기획서 12장 생태 오류 체크리스트에 걸리지 않는다.
- [ ] 국명·단계 용어가 4장과 같다.
- [ ] 길이가 5번 기준 안이다.
- [ ] 루틴 칸 결과는 며칠의 습관이고, 한 장면은 이벤트에 두었다(3.6).
- [ ] 맞춤법·띄어쓰기를 확인했다.
